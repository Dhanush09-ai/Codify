# Chapter 10: Structures

## Section 4: C Problem Solving & Debugging

Writing a C program is not only about knowing the syntax.

You also need to know how to:

* Understand a problem
* Break it into smaller steps
* Write an algorithm
* Write the C program
* Test the program
* Find errors
* Debug the program
* Improve the solution

These skills are called **problem solving and debugging**.

---

## 1. What is Problem Solving?

**Problem solving** is the process of understanding a problem and developing a step-by-step solution.

For example:

> Find the largest number among three numbers.

Before writing C code, we should understand what the program needs to do.

### Basic Problem-Solving Process

```text
Understand the Problem
        ↓
Identify Inputs
        ↓
Identify Output
        ↓
Plan the Solution
        ↓
Write the Algorithm
        ↓
Write C Code
        ↓
Test the Program
        ↓
Debug if Needed
```

---

## 2. Understand the Problem

The first step is to clearly understand what the problem is asking.

Consider:

> Write a program to calculate the area of a rectangle.

We need to identify:

* Input: length and width
* Formula: `area = length × width`
* Output: area

Only after understanding these requirements should we start writing the program.

---

## 3. Identify Inputs and Outputs

Every programming problem normally has some **inputs** and **outputs**.

For example:

> Find the sum of two numbers.

### Input

```text
Two numbers
```

### Processing

```text
sum = first number + second number
```

### Output

```text
The sum
```

This can be represented as:

```text
Input → Processing → Output
```

---

## 4. Example: Find the Largest of Two Numbers

Problem:

> Write a program to find the larger of two numbers.

### Step 1: Identify Input

```text
Two integers
```

### Step 2: Identify Output

```text
The larger integer
```

### Step 3: Plan the Logic

```text
Read a and b

If a > b
    print a
Otherwise
    print b
```

### Step 4: Write the Program

```c
#include <stdio.h>

int main() {
    int a, b;

    printf("Enter two numbers: ");
    scanf("%d %d", &a, &b);

    if (a > b)
        printf("Largest = %d", a);
    else
        printf("Largest = %d", b);

    return 0;
}
```

Example:

```output
Enter two numbers: 25 18
Largest = 25
```

## 5. Break a Large Problem into Smaller Parts

A large problem can be difficult to solve all at once.

Instead, divide it into smaller tasks.

For example, consider a **student marks program**.

Instead of thinking about the entire program at once, divide it into:

1. Read student details
2. Read marks
3. Calculate total
4. Calculate average
5. Decide pass/fail
6. Display the result

This makes the program easier to understand and debug.

---

## 6. Write an Algorithm

An **algorithm** is a step-by-step procedure for solving a problem.

Example:

> Find the sum of numbers from 1 to 5.

### Algorithm

```text
1. Start
2. Set sum = 0
3. Set number = 1
4. Add number to sum
5. Increase number by 1
6. Repeat until number becomes 5
7. Display sum
8. Stop
```

The algorithm helps us plan the solution before writing C code.

---

## 7. Convert the Algorithm into C Code

After creating the algorithm, we can convert it into C.

```c
#include <stdio.h>

int main() {
    int sum = 0;
    int i;

    for (i = 1; i <= 5; i++) {
        sum = sum + i;
    }

    printf("Sum = %d", sum);

    return 0;
}
```

```output
Sum = 15
```

The algorithm describes **what to do**, while the C program describes **how to perform it using C syntax**.

---

## 8. Test Cases

A **test case** is a particular input used to check whether a program works correctly.

For example:

```c
int a = 10;
int b = 20;
```

Expected output:

```output
Largest = 20
```

We should test programs with different types of inputs.

### Example Test Cases

| Input    | Expected Output |
| -------- | --------------- |
| `10 20`  | `20`            |
| `50 30`  | `50`            |
| `5 5`    | `5`             |
| `-10 -5` | `-5`            |

Testing different inputs can help us find problems that are not visible with only one example.

## 9. What is Debugging?

**Debugging** is the process of finding and fixing errors in a program.

Errors in programs are commonly called **bugs**.

For example:

```c
int a = 10;
int b = 20;

printf("%d", a - b);
```

If the intended operation was addition, the program contains a logical mistake.

The program may compile successfully, but the result is incorrect.

Debugging helps us find and correct such problems.

---

## 10. Types of Errors

There are three important types of errors beginners should understand:

1. Syntax errors
2. Runtime errors
3. Logical errors

---

## 11. Syntax Errors

A **syntax error** occurs when the code does not follow the rules of the C language.

Example:

```c
#include <stdio.h>

int main() {
    printf("Hello")
    return 0;
}
```

The semicolon after `printf()` is missing.

Correct version:

```c
#include <stdio.h>

int main() {
    printf("Hello");
    return 0;
}
```

The compiler normally reports syntax-related errors while compiling the program.

---

## 12. Runtime Errors

A **runtime error** occurs while the program is running.

One common example is division by zero.

```c
#include <stdio.h>

int main() {
    int a = 10;
    int b = 0;

    printf("%d", a / b);

    return 0;
}
```

The program attempts to divide by zero, which is an invalid operation.

The important point is that some problems are discovered only when the program executes.

---

## 13. Logical Errors

A **logical error** occurs when the program runs but produces the wrong result because the logic is incorrect.

Example:

```c
#include <stdio.h>

int main() {
    int length = 10;
    int width = 5;

    int area = length + width;

    printf("Area = %d", area);

    return 0;
}
```

The program may run successfully, but the formula for rectangle area is incorrect.

The correct formula is:

```text
area = length × width
```

Correct code:

```c
int area = length * width;
```

This is a **logical error**.

---

## 14. Syntax vs Runtime vs Logical Errors

| Error Type    | When It Happens    | Example                                    |
| ------------- | ------------------ | ------------------------------------------ |
| Syntax Error  | During compilation | Missing `;`                                |
| Runtime Error | During execution   | Invalid operation such as division by zero |
| Logical Error | Program runs       | Wrong formula or condition                 |

---

## 15. Using `printf()` for Debugging

One simple debugging technique is to use `printf()` to check the values of variables.

Consider:

```c
#include <stdio.h>

int main() {
    int a = 10;
    int b = 20;
    int sum;

    sum = a + b;

    printf("sum = %d\n", sum);

    return 0;
}
```

The `printf()` statement helps us see the value stored in `sum`.

We can also check intermediate values:

```c
printf("a = %d\n", a);
printf("b = %d\n", b);
printf("sum = %d\n", sum);
```

This can help identify where the program starts producing an unexpected value.

---

## 16. Debugging with Intermediate Values

Consider a program that calculates an average:

```c
#include <stdio.h>

int main() {
    int a = 80;
    int b = 90;
    int c = 70;

    int total = a + b + c;
    int average = total / 3;

    printf("Total = %d\n", total);
    printf("Average = %d\n", average);

    return 0;
}
```

```output
Total = 240
Average = 80
```

Printing intermediate results makes it easier to check each step.

## 17. Trace the Program Step by Step

**Tracing** means following the program's execution step by step.

Consider:

```c
int sum = 0;

for (int i = 1; i <= 3; i++) {
    sum = sum + i;
}
```

We can trace it like this:

| `i` | `sum` before | `sum` after |
| --: | -----------: | ----------: |
|   1 |            0 |           1 |
|   2 |            1 |           3 |
|   3 |            3 |           6 |

Final value:

```text
sum = 6
```

Tracing is especially useful when debugging loops.

---

## 18. Check Conditions Carefully

Many logical errors occur because of incorrect conditions.

Example:

```c
if (marks > 40)
    printf("Pass");
else
    printf("Fail");
```

If the requirement says a student passes with **40 or above**, the condition should be:

```c
if (marks >= 40)
```

Small differences such as:

* `>`
* `>=`
* `<`
* `<=`
* `==`
* `!=`

can change the result of a program.

---

## 19. Check Loop Conditions

Loops are another common source of bugs.

Example:

```c
for (int i = 1; i <= 5; i++) {
    printf("%d ", i);
}
```

Output:

```output
1 2 3 4 5
```

If we accidentally write:

```c
for (int i = 1; i < 5; i++) {
    printf("%d ", i);
}
```

Output becomes:

```output
1 2 3 4
```

The condition determines how many times the loop executes.

---

## 20. Check Array Indexes

Array indexing is another common area for mistakes.

Consider:

```c
int numbers[5] = {10, 20, 30, 40, 50};
```

Valid indexes are:

```text
0 1 2 3 4
```

So this is valid:

```c
printf("%d", numbers[4]);
```

But accessing:

```c
printf("%d", numbers[5]);
```

is outside the valid range of the array.

Always check array boundaries carefully.

---

## 21. Check Input Values

A program should also be tested with different input values.

For example, if a program finds the largest number, test:

```text
Positive numbers
Negative numbers
Equal numbers
Zero
```

For example:

```text
10 20
20 10
10 10
-5 -2
0 10
```

This helps reveal logical problems.

---

## 22. Debugging Strategy

When a program does not work correctly, follow a systematic approach.

### Step 1: Read the Error

If the compiler gives an error message, read it carefully.

### Step 2: Find the Reported Line

Check the line mentioned by the compiler.

### Step 3: Check Nearby Code

Sometimes the actual mistake can be slightly before the reported line.

### Step 4: Check Variables

Print important variables using `printf()`.

### Step 5: Check Conditions

Make sure `if` and loop conditions match the problem.

### Step 6: Check Formulas

Verify mathematical calculations.

### Step 7: Test Again

Run the program with multiple test cases.

---

## 23. Example: Finding a Logical Error

Suppose we want to calculate the average of three marks.

Incorrect program:

```c
#include <stdio.h>

int main() {
    int a = 80;
    int b = 90;
    int c = 70;

    int average = a + b + c / 3;

    printf("Average = %d", average);

    return 0;
}
```

The expression does not calculate the intended average because division has higher precedence than addition.

We should use parentheses:

```c
int average = (a + b + c) / 3;
```

Now the program calculates the total first and then divides it by `3`.

## 24. Problem Solving Example

### Problem

> Find the sum of all even numbers from 1 to 10.

### Step 1: Understand

We need to add:

```text
2 + 4 + 6 + 8 + 10
```

### Step 2: Plan

Start with:

```text
sum = 0
```

Then check each number from `1` to `10`.

If the number is even, add it to `sum`.

### Step 3: Write the Program

```c
#include <stdio.h>

int main() {
    int sum = 0;

    for (int i = 1; i <= 10; i++) {
        if (i % 2 == 0) {
            sum = sum + i;
        }
    }

    printf("Sum = %d", sum);

    return 0;
}
```

```output
Sum = 30
```

### Step 4: Test

The even numbers are:

```text
2, 4, 6, 8, 10
```

Their sum is:

```text
30
```

## ⚠️ Common Mistakes

### Mistake 1: Starting to Code Without Understanding the Problem

Always identify the input, processing, and output first.

### Mistake 2: Testing Only One Input

One test case may not reveal all problems.

Test normal, boundary, zero, negative, and equal values when they are valid for the problem.

### Mistake 3: Ignoring Compiler Errors

Read the compiler message and check the reported line and nearby code.

### Mistake 4: Confusing `=` and `==`

```c
if (a == 10)
```

checks whether `a` is equal to `10`.

```c
a = 10;
```

assigns `10` to `a`.

### Mistake 5: Wrong Loop Boundary

Carefully check whether the loop should use `<` or `<=`.

### Mistake 6: Wrong Array Index

For an array with 5 elements, the valid indexes are `0` through `4`.

### Mistake 7: Wrong Formula

Write the mathematical formula first and then convert it into C code.

## 🔑 Key Points

* Problem solving means developing a logical solution to a programming problem.
* First understand the problem before writing code.
* Identify inputs, processing, and outputs.
* Break large problems into smaller tasks.
* An algorithm gives step-by-step instructions for solving a problem.
* Test cases help verify whether a program works correctly.
* Debugging means finding and fixing program errors.
* Syntax errors are related to incorrect C syntax.
* Runtime errors happen while the program executes.
* Logical errors produce incorrect results even when the program runs.
* `printf()` can be useful for checking intermediate values.
* Tracing helps understand how variables change during execution.
* Always check conditions, loops, formulas, and array indexes.
* Test programs with multiple suitable inputs.
