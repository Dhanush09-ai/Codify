# Chapter 8: HTML Forms

## Section 1: The Form Container

HTML forms allow users to **enter and submit information** on a webpage.

Forms are used everywhere on the web:

* Login pages
* Registration pages
* Search boxes
* Contact forms
* Feedback forms
* Online applications
* Checkout pages

The main container for an HTML form is the `<form>` element.

> **Simple idea:** The `<form>` element acts as a container that holds the controls users use to enter and submit information.

---

## 1. What Is an HTML Form?

An HTML form is an area of a webpage where users can enter information.

For example, a login form may contain:

```text
+---------------------------+
|          Login            |
|                           |
| Username: [___________]   |
| Password: [___________]   |
|                           |
|          [ Login ]        |
+---------------------------+
```

The HTML structure might contain:

```html
<form>
    <!-- Form controls go here -->
</form>
```

The `<form>` element provides the main structure for collecting user input.

---

## 2. The `<form>` Element

The basic syntax is:

```html
<form>
    Form controls
</form>
```

Example:

```html
<form>
    <label>Name:</label>
    <input type="text">

    <button type="submit">Submit</button>
</form>
```

Here:

```text
<form>   → Form container
<label>  → Text describing the input
<input>  → Input control
<button> → Submit button
```

The `<form>` element groups these controls together as one form.

---

## 3. Why Do We Need a Form Container?

Imagine a registration page with:

```text
Name
Email
Password
Phone
Address
Submit
```

These controls belong to the same task: **registering a user**.

The `<form>` element groups them together.

Example:

```html
<form>

    <label>Name:</label>
    <input type="text">

    <label>Email:</label>
    <input type="email">

    <label>Password:</label>
    <input type="password">

    <button type="submit">Register</button>

</form>
```

The form tells the browser that these controls are part of the same form.

---

## 4. Basic Form Example

```html
<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="UTF-8">
    <title>Contact Form</title>
</head>

<body>

    <h1>Contact Us</h1>

    <form>

        <label for="name">Name:</label>
        <input type="text" id="name">

        <br><br>

        <label for="email">Email:</label>
        <input type="email" id="email">

        <br><br>

        <button type="submit">Send</button>

    </form>

</body>

</html>
```

This creates a simple contact form.

---

## 5. The `action` Attribute

The `<form>` element can have an `action` attribute.

Example:

```html
<form action="/submit">
    ...
</form>
```

The `action` attribute specifies the **URL where the form data is sent when the form is submitted**.

Think of it as:

```text
User enters data
       ↓
    Submit
       ↓
 Form sends data
       ↓
 /submit
```

For example:

```html
<form action="/register">
    ...
</form>
```

This indicates that the form is intended to send its data to:

```text
/register
```

---

## 6. Real-World Example of `action`

Suppose a website has a registration form.

```html
<form action="/register">

    <label for="username">Username:</label>
    <input type="text" id="username">

    <label for="email">Email:</label>
    <input type="email" id="email">

    <button type="submit">Create Account</button>

</form>
```

When the user submits the form, the browser sends the form data to the URL specified by `action`.

> **Important:** The `action` attribute specifies the destination. The server at that destination is responsible for processing the submitted information.

---

## 7. The `method` Attribute

The `method` attribute specifies **how the form data is sent**.

Two common methods are:

```text
GET
POST
```

Example:

```html
<form action="/search" method="get">
    ...
</form>
```

Another example:

```html
<form action="/register" method="post">
    ...
</form>
```

---

## 8. GET Method

The `GET` method sends form data as part of the URL.

Example:

```html
<form action="/search" method="get">

    <input type="search" name="q">

    <button type="submit">Search</button>

</form>
```

If the user searches for:

```text
HTML
```

the resulting request may have a URL similar to:

```text
/search?q=HTML
```

GET is commonly useful for requests such as:

* Search
* Filtering
* Queries
* Information retrieval

---

## 9. POST Method

The `POST` method sends form data in the request body rather than putting it into the URL.

Example:

```html
<form action="/register" method="post">

    <label for="name">Name:</label>
    <input type="text" id="name" name="name">

    <label for="email">Email:</label>
    <input type="email" id="email" name="email">

    <button type="submit">Register</button>

</form>
```

POST is commonly used when submitting data that creates or changes information on a server.

Examples include:

* Registration
* Login
* Creating a post
* Updating account information
* Submitting an application

> **Important:** Using `POST` does not by itself encrypt data. For sensitive information, websites should use HTTPS.

---

## 10. GET vs POST

| Method | Main idea                 | Common example |
| :----- | :------------------------ | :------------- |
| `GET`  | Requests information      | Search         |
| `POST` | Sends data for processing | Registration   |

Easy way to remember:

```text
GET  → Get information
POST → Send information
```

The exact choice depends on what the form is intended to do.

---

## 11. The `name` Attribute

Form controls usually need a `name` attribute when their values are going to be submitted.

Example:

```html
<input type="text" name="username">
```

The `name` identifies the submitted value.

For example:

```html
<input type="text" name="username">
```

If the user enters:

```text
Owais
```

the submitted data can contain:

```text
username=Owais
```

Think of it as:

```text
name  → label used for submitted data
value → information entered by the user
```

---

## 12. Why `name` Is Important

Consider:

```html
<form action="/login" method="post">

    <input type="text" name="username">

    <input type="password" name="password">

    <button type="submit">Login</button>

</form>
```

The server can identify the submitted values using:

```text
username
password
```

Without appropriate names, form controls may not provide useful name/value pairs during normal form submission.

---

## 13. The `autocomplete` Attribute

The `<form>` element can also use `autocomplete`.

Example:

```html
<form autocomplete="on">
    ...
</form>
```

This allows the browser to use previously entered information where appropriate.

For example, browsers may help users fill in:

* Name
* Email
* Address
* Phone number

A form can also disable autocomplete:

```html
<form autocomplete="off">
    ...
</form>
```

However, browsers may make their own decisions about autocomplete behavior in some situations.

---

## 14. The `novalidate` Attribute

Forms normally perform built-in browser validation for certain input types and attributes.

For example:

```html
<input type="email" required>
```

The browser can check that the field has been filled and that the value looks like an email address.

The `novalidate` attribute can disable the browser's built-in form validation when the form is submitted.

Example:

```html
<form novalidate>
    ...
</form>
```

This does not mean that validation is unnecessary. It means the browser's built-in validation is disabled for that form.

---

## 15. The `target` Attribute

The `target` attribute controls where the response to a form submission is displayed.

For example:

```html
<form action="/search" method="get" target="_blank">
    ...
</form>
```

This can request that the result be opened in a new browsing context.

Common target values include:

```text
_self
_blank
```

`_self` is the normal default behavior.

`_blank` requests a new browsing context.

---

## 16. A Complete Form Example

```html
<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="UTF-8">

    <meta
        name="viewport"
        content="width=device-width, initial-scale=1.0"
    >

    <title>Registration Form</title>
</head>

<body>

    <h1>Create an Account</h1>

    <form
        action="/register"
        method="post"
        autocomplete="on"
    >

        <label for="name">Full Name:</label>
        <input
            type="text"
            id="name"
            name="name"
            required
        >

        <br><br>

        <label for="email">Email:</label>
        <input
            type="email"
            id="email"
            name="email"
            required
        >

        <br><br>

        <label for="password">Password:</label>
        <input
            type="password"
            id="password"
            name="password"
            required
        >

        <br><br>

        <button type="submit">Register</button>

    </form>

</body>

</html>
```

This example uses several important concepts:

```text
<form>         → Form container
action         → Submission destination
method         → Submission method
autocomplete   → Browser assistance
name           → Submitted field name
required       → Basic validation
```

## 17. Form Controls Belong Inside the Form

A common structure is:

```html
<form>

    <label for="name">Name:</label>
    <input type="text" id="name" name="name">

    <label for="email">Email:</label>
    <input type="email" id="email" name="email">

    <button type="submit">Submit</button>

</form>
```

The controls are inside the `<form>` container.

Conceptually:

```text
<form>
    ┌─────────────────────────┐
    │ Name      [___________]  │
    │ Email     [___________]  │
    │                         │
    │          [ Submit ]     │
    └─────────────────────────┘
</form>
```

---

## 18. The `form` Attribute on Controls

HTML also allows certain form-associated controls to specify which form they belong to using the `form` attribute.

Example:

```html
<form id="studentForm">
    <input type="text" name="name">
</form>

<button type="submit" form="studentForm">
    Submit
</button>
```

Here, the button is outside the `<form>` element but is associated with it using:

```html
form="studentForm"
```

This is useful in special layouts, but keeping controls inside the form is usually simpler when possible.

---

## 19. Form Submission Flow

A simple form submission can be understood like this:

```text
User enters information
          ↓
     Form controls
          ↓
     User clicks Submit
          ↓
   Browser creates data
          ↓
   action + method
          ↓
       Server
```

For example:

```html
<form action="/login" method="post">
```

means:

```text
Destination → /login
Method      → POST
```

## 20. Real-World Example: Search Form

A search form can use GET because the search information can be represented in the URL.

```html
<form action="/search" method="get">

    <label for="search">Search:</label>

    <input
        type="search"
        id="search"
        name="q"
    >

    <button type="submit">Search</button>

```

If the user searches for:

```text
HTML forms
```

the request URL may look like:

```text
/search?q=HTML+forms
```

This makes search URLs easy to bookmark and share.

## 22. Common Mistakes

### Mistake 1: Forgetting the `<form>` element

Incorrect:

```html
<input type="text">
<input type="email">
<button>Submit</button>
```

These controls are not grouped inside a form.

Better:

```html
<form>

    <input type="text">
    <input type="email">

    <button type="submit">Submit</button>

</form>
```

---

### Mistake 2: Forgetting `name`

Example:

```html
<input type="text" id="username">
```

For normal form submission, it is better to provide:

```html
<input
    type="text"
    id="username"
    name="username"
>
```

The `id` is useful for associating the `<label>` with the control.

The `name` identifies the field in submitted form data.

---

### Mistake 3: Confusing `id` and `name`

These attributes have different purposes.

```html
<input
    type="text"
    id="username"
    name="username"
>
```

Think:

```text
id   → identifies the element in the document
name → identifies the submitted form field
```

They often have the same value, but they serve different purposes.

---

### Mistake 4: Assuming POST Means Encryption

This is incorrect:

```text
POST = encrypted
```

POST only changes how the data is transmitted in the HTTP request.

For secure transmission, use:

```text
HTTPS
```

---

## 23. Accessibility Tip

Forms should use labels that clearly describe their controls.

Good:

```html
<label for="email">Email Address:</label>

<input
    type="email"
    id="email"
    name="email"
>
```

The `for` value:

```text
email
```

matches the input's:

```text
id="email"
```

This connects the label to the input and improves usability and accessibility.

## Key Points

* `<form>` is the main container for form controls.
* Forms are used to collect and submit user information.
* `action` specifies where the submitted data is sent.
* `method` specifies how the data is submitted.
* Common methods are `GET` and `POST`.
* `GET` is commonly useful for searches and information retrieval.
* `POST` is commonly used when sending data for processing or creating/updating information.
* `name` identifies a form field in submitted data.
* `id` identifies an element in the document and can connect it to a `<label>`.
* `autocomplete` controls browser assistance with previously entered information.
* `novalidate` disables the browser's built-in validation for the form.
* `target` controls where the submission response is displayed.
* Form controls are normally placed inside the `<form>` element.
* Use meaningful `<label>` elements for form controls.
* POST does not provide encryption; HTTPS is used for secure transmission.
