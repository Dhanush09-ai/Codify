# Chapter 8: HTML Forms

## Section 5: Native Form Validation

Form validation checks whether the information entered by a user is acceptable before the form is submitted.

HTML provides **native form validation**, which means the browser can perform many basic validation checks without JavaScript.

For example:

```html
<label for="email">Email:</label>

<input
    type="email"
    id="email"
    name="email"
    required
>

<button type="submit">Submit</button>
```

If the user leaves the field empty or enters an invalid email format, the browser can show a validation message.

> **Simple idea:** Native validation lets HTML handle many common form-checking tasks automatically.

---

## 1. Why Form Validation Is Important

Imagine a registration form:

```text
Name:     [____________]
Email:    [____________]
Password: [____________]

          [ Register ]
```

What happens if the user:

* Leaves the name empty?
* Enters an invalid email?
* Enters a password that is too short?
* Enters a number outside the allowed range?

Validation helps prevent incorrect or incomplete information from being submitted.

---

## 2. The `required` Attribute

The `required` attribute makes a form control mandatory.

Example:

```html
<label for="name">Full Name:</label>

<input
    type="text"
    id="name"
    name="name"
    required
>
```

The user must provide a value before the form can normally be submitted.

Without `required`:

```html
<input type="text" name="name">
```

the field can be left empty.

---

## 3. Required Email Field

Example:

```html
<label for="email">Email Address:</label>

<input
    type="email"
    id="email"
    name="email"
    required
>
```

Two checks can now work together:

```text
required
   ↓
Value must be provided

type="email"
   ↓
Value should have an email-like format
```

---

## 4. Email Validation

The `email` input type provides built-in browser validation.

Example:

```html
<input
    type="email"
    name="email"
    required
>
```

A value such as:

```text
student@example.com
```

has a normal email format.

A value such as:

```text
student
```

may be rejected by the browser's native validation.

The exact validation behavior and message can vary between browsers.

---

## 5. URL Validation

The `url` input type is useful for web addresses.

Example:

```html
<label for="website">Website:</label>

<input
    type="url"
    id="website"
    name="website"
>
```

The browser can check whether the entered value has a URL-like format.

For example:

```text
https://example.com
```

is a typical URL value.

---

## 6. Number Validation

The `number` input type can be combined with `min` and `max`.

Example:

```html
<label for="age">Age:</label>

<input
    type="number"
    id="age"
    name="age"
    min="18"
    max="60"
>
```

This tells the browser that the acceptable range is:

```text
18 → 60
```

A value below `18` or above `60` can fail native constraint validation.

---

## 7. The `min` Attribute

`min` specifies the minimum allowed value.

Example:

```html
<input
    type="number"
    name="marks"
    min="0"
>
```

The value should not be below `0`.

For a date:

```html
<input
    type="date"
    name="date"
    min="2026-01-01"
>
```

The selected date should not be earlier than the specified minimum.

---

## 8. The `max` Attribute

`max` specifies the maximum allowed value.

Example:

```html
<input
    type="number"
    name="marks"
    max="100"
>
```

The value should not be greater than `100`.

You can combine `min` and `max`:

```html
<input
    type="number"
    name="marks"
    min="0"
    max="100"
>
```

This creates a range from `0` to `100`.

---

## 9. The `minlength` Attribute

`minlength` specifies the minimum number of characters.

Example:

```html
<label for="username">Username:</label>

<input
    type="text"
    id="username"
    name="username"
    minlength="3"
    required
>
```

The username must contain at least 3 characters.

For example:

```text
OK:
ABC

Not enough:
AB
```

---

## 10. The `maxlength` Attribute

`maxlength` specifies the maximum number of characters.

Example:

```html
<label for="username">Username:</label>

<input
    type="text"
    id="username"
    name="username"
    maxlength="20"
>
```

The user can enter up to 20 characters.

This is useful for fields such as:

* Usernames
* Short titles
* Names
* Codes

---

## 11. Combining `minlength` and `maxlength`

You can use both attributes together.

Example:

```html
<input
    type="text"
    name="username"
    minlength="3"
    maxlength="20"
    required
>
```

This means:

```text
Minimum → 3 characters
Maximum → 20 characters
Required → Yes
```

---

## 12. The `pattern` Attribute

The `pattern` attribute allows you to specify a pattern that the value must match.

Example:

```html
<label for="code">Student Code:</label>

<input
    type="text"
    id="code"
    name="code"
    pattern="[A-Z]{3}[0-9]{3}"
    required
>
```

This pattern expects:

```text
3 uppercase letters + 3 digits
```

Examples:

```text
CME123
ECE456
AIM789
```

---

## 13. Understanding a Pattern

Consider:

```html
pattern="[A-Z]{3}[0-9]{3}"
```

Break it down:

```text
[A-Z]
   ↓
One uppercase letter

{3}
   ↓
Exactly three of them

[0-9]
   ↓
One digit

{3}
   ↓
Exactly three digits
```

Therefore:

```text
ABC123
```

matches the pattern.

---

## 14. `step` Validation

The `step` attribute controls the allowed increments for certain inputs.

Example:

```html
<input
    type="number"
    name="quantity"
    min="0"
    max="20"
    step="2"
>
```

Possible values include:

```text
0
2
4
6
8
...
20
```

A value such as `5` does not follow the specified step from the minimum and can fail validation.

---

## 15. `required`, `min`, `max`, and `step` Together

Example:

```html
<label for="quantity">Quantity:</label>

<input
    type="number"
    id="quantity"
    name="quantity"
    min="1"
    max="10"
    step="1"
    required
>
```

This means:

```text
Required → Yes
Minimum  → 1
Maximum  → 10
Step     → 1
```

---

## 16. Date Validation

Date inputs can also use `min` and `max`.

Example:

```html
<label for="dob">Date of Birth:</label>

<input
    type="date"
    id="dob"
    name="dob"
    min="1950-01-01"
    max="2010-12-31"
>
```

The browser can prevent dates outside the specified range from passing native constraint validation.

---

## 17. Date and Time Validation

`datetime-local` can also have limits.

Example:

```html
<label for="meeting">Meeting:</label>

<input
    type="datetime-local"
    id="meeting"
    name="meeting"
    min="2026-10-01T09:00"
    max="2026-10-01T18:00"
>
```

This allows a time within the specified range.

---

## 18. File Validation

File inputs can use the `accept` attribute.

Example:

```html
<label for="resume">Resume:</label>

<input
    type="file"
    id="resume"
    name="resume"
    accept=".pdf"
>
```

This provides a hint to the browser about the desired file type.

However:

> `accept` is not a complete security validation mechanism.

The server should independently validate uploaded files.

---

## 19. The `novalidate` Attribute

Normally, a form can use the browser's native validation.

You can disable that validation for a particular form using `novalidate`.

Example:

```html
<form action="/submit" method="post" novalidate>

    <label for="email">Email:</label>

    <input
        type="email"
        id="email"
        name="email"
        required
    >

    <button type="submit">Submit</button>

</form>
```

With `novalidate`, the browser's normal constraint-validation UI is bypassed when the form is submitted.

This does **not** mean the server should accept invalid data.

---

## 20. `formnovalidate`

`formnovalidate` can be placed on a submit button.

Example:

```html
<form action="/submit" method="post">

    <label for="email">Email:</label>

    <input
        type="email"
        id="email"
        name="email"
        required
    >

    <button type="submit">
        Submit
    </button>

    <button
        type="submit"
        formnovalidate
    >
        Save Draft
    </button>

</form>
```

Here, the normal submit button uses validation.

The `Save Draft` button can bypass the browser's constraint validation.

---

## 21. Native Validation Messages

When a form fails native validation, browsers can display their own messages.

For example:

```text
Please fill out this field.
```

or:

```text
Please enter a valid email address.
```

The exact wording and appearance depend on the browser and operating system.

You should therefore focus on creating correct HTML constraints rather than depending on one browser's exact message.

---

## 22. Validation With `checkValidity()`

JavaScript can ask whether a form control or form passes constraint validation.

Example:

```html
<input
    type="email"
    id="email"
    name="email"
    required
>

<script>
const email = document.getElementById("email");

console.log(email.checkValidity());
</script>
```

`checkValidity()` returns:

```text
true  → The element passes validation
false → The element fails validation
```

---

## 23. `reportValidity()`

`reportValidity()` checks validity and can ask the browser to report the validation problem to the user.

Example:

```html
<script>
const email = document.getElementById("email");

email.reportValidity();
</script>
```

If the value is invalid, the browser can display its native validation message.

---

## 24. The `validity` Property

The `validity` property provides information about the validation state.

Example:

```html
<script>
const email = document.getElementById("email");

console.log(email.validity.valid);
</script>
```

Some useful properties include:

```text
valid
valueMissing
typeMismatch
tooShort
tooLong
rangeUnderflow
rangeOverflow
stepMismatch
patternMismatch
```

For example:

```javascript
email.validity.valueMissing
```

can indicate that a required value is missing.

---

## 25. `:valid` and `:invalid`

CSS provides pseudo-classes that can respond to validation state.

Example:

```html
<style>
input:invalid {
    border: 2px solid red;
}

input:valid {
    border: 2px solid green;
}
</style>
```

These selectors can style controls based on whether their current value passes constraint validation.

> When designing accessible forms, do not rely only on color to communicate errors or success. Provide clear text when necessary.

## 27. Native Validation vs JavaScript Validation

Native HTML validation is useful for common requirements.

### Native HTML validation

```html
<input
    type="email"
    required
>
```

Advantages:

* Simple
* Built into the browser
* Requires less code
* Works without custom JavaScript

### JavaScript validation

JavaScript is useful when validation requires custom logic.

For example:

```text
Password must match Confirm Password
```

or:

```text
Username must be checked against a server
```

HTML can provide basic constraints, while JavaScript can add more interactive behavior when necessary.

---

## 28. Client-Side Validation Is Not Security

Native validation happens in the browser.

A user can disable or bypass client-side validation.

Therefore:

```text
Browser validation
        ↓
Good user experience

Server-side validation
        ↓
Important for data integrity and security
```

For example, even if HTML says:

```html
<input
    type="number"
    name="age"
    min="18"
>
```

the server should still check the received age.

Never assume that browser validation alone makes submitted data trustworthy.

## 30. Common Validation Mistakes

### Mistake 1: Using only JavaScript for simple validation

Instead of writing unnecessary JavaScript for:

```text
Required field
Email format
Minimum number
Maximum number
```

use the appropriate HTML attributes where they meet the requirement.

---

### Mistake 2: Assuming `required` checks everything

This:

```html
<input type="text" required>
```

only ensures that a value is provided.

It does not automatically know whether the value is meaningful for your application's specific rules.

---

### Mistake 3: Using `min` and `max` as character limits

For text length, use:

```html
minlength="5"
maxlength="20"
```

For numeric ranges, use:

```html
min="5"
max="20"
```

Remember:

```text
min / max
    → Numeric/date limits

minlength / maxlength
    → Character limits
```

---

### Mistake 4: Trusting browser validation

Never treat browser validation as the final security check.

Always validate important submitted data on the server.

## 31. Validation Attribute Quick Reference

| Attribute        | Purpose                                            |
| :--------------- | :------------------------------------------------- |
| `required`       | Requires a value                                   |
| `min`            | Sets minimum numeric/date value                    |
| `max`            | Sets maximum numeric/date value                    |
| `step`           | Sets allowed increments                            |
| `minlength`      | Sets minimum text length                           |
| `maxlength`      | Sets maximum text length                           |
| `pattern`        | Specifies a value pattern                          |
| `accept`         | Provides a file-type selection hint                |
| `novalidate`     | Disables normal form constraint-validation UI      |
| `formnovalidate` | Bypasses constraint validation for a submit button |

---

## 32. Key Points

* Native form validation is provided directly by HTML and the browser.
* `required` makes a field mandatory.
* `type="email"` provides email-format validation.
* `type="url"` provides URL-format validation.
* `min` and `max` can limit numeric or date values.
* `minlength` and `maxlength` control text length.
* `step` controls allowed increments for supported inputs.
* `pattern` allows values to be checked against a specified pattern.
* `accept` provides a hint for file selection.
* `novalidate` can disable normal form constraint-validation UI.
* `formnovalidate` can bypass validation for a particular submit button.
* `checkValidity()` can check whether a control or form passes validation.
* `reportValidity()` can report a validation problem to the user.
* The `validity` property provides detailed validation-state information.
* CSS `:valid` and `:invalid` can style controls based on their validation state.
* Native validation is useful for user experience.
* Client-side validation should never replace server-side validation.
