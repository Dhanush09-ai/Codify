# Chapter 2: HTML Building Blocks

## Section 4: Code Formatting & Comments

As HTML documents become larger, writing clean and organized code becomes important.

Good **formatting** makes HTML easier to read, understand, and maintain. **Comments** allow developers to leave notes inside the code without displaying those notes on the webpage.

> **Simple idea:** Formatting makes code easier to read, while comments help explain the code.

---

### 1. What Is Code Formatting?

**Code formatting** means arranging your HTML code in a clean and consistent way.

For example, this code works:

```html
<div><h1>Welcome</h1><p>Learn HTML with CODIFY.</p></div>
```

But it is difficult to read.

A better format is:

```html
<div>
    <h1>Welcome</h1>
    <p>Learn HTML with CODIFY.</p>
</div>
```

Both examples represent the same basic HTML structure, but the second one is easier for a developer to understand.

---

### 2. Why Is Formatting Important?

Good formatting helps us:

* Read code more easily.
* Understand the structure of a webpage.
* Find mistakes faster.
* Maintain large projects.
* Work with other developers.
* See which elements are nested inside other elements.

> **Remember:** Clean code is easier to understand and maintain.

---

### 3. Indentation

**Indentation** means adding spaces at the beginning of a line to show the structure of the code.

For example:

```html
<div>
    <h1>My Website</h1>
    <p>Welcome to my website.</p>
</div>
```

The `<h1>` and `<p>` elements are indented because they are inside the `<div>`.

For nested elements, indentation makes the relationship easier to see:

```html
<div>
    <section>
        <h2>About Us</h2>
        <p>Learn more about our college.</p>
    </section>
</div>
```

The indentation shows the structure clearly.

---

### 4. Consistent Indentation

Use a consistent indentation style throughout your project.

For example:

```html
<div>
    <h1>CODIFY</h1>
    <p>Learn HTML.</p>
</div>
```

Avoid mixing different indentation styles randomly.

For example:

```html
<div>
<h1>CODIFY</h1>
    <p>Learn HTML.</p>
      <section>
    </section>
</div>
```

The second example is harder to read because the indentation is inconsistent.

Many code editors can automatically format or indent HTML code.

---

### 5. Proper Nesting and Formatting

Formatting becomes especially useful when HTML elements are nested.

Consider:

```html
<ul>
    <li>HTML</li>
    <li>CSS</li>
    <li>JavaScript</li>
</ul>
```

The indentation makes it clear that each `<li>` element is inside the `<ul>`.

A more complex example:

```html
<section>
    <h2>Courses</h2>

    <div>
        <h3>HTML</h3>
        <p>Learn the basics of HTML.</p>
    </div>

    <div>
        <h3>CSS</h3>
        <p>Learn how to style webpages.</p>
    </div>
</section>
```

Without indentation, understanding this structure would be more difficult.

---

### 6. Blank Lines

Blank lines can be used to separate different sections of HTML.

For example:

```html
<h1>Student Portal</h1>

<p>Welcome to the student portal.</p>

<h2>Courses</h2>

<p>View your available courses.</p>
```

Blank lines do not normally change how the browser displays the webpage.

They mainly make the source code easier for developers to read.

> **Simple idea:** Blank lines are for **human readability**, not for creating visible spacing on the webpage.

---

### 7. What Are Comments?

A **comment** is a note written inside the HTML source code.

HTML comments use this syntax:

```html
<!-- This is a comment -->
```

The browser does not display the comment as normal webpage content.

For example:

```html
<h1>Welcome to CODIFY</h1>

<!-- This paragraph contains the course introduction -->
<p>Learn HTML step by step.</p>
```

The user sees:

```text
Welcome to CODIFY

Learn HTML step by step.
```

The comment remains in the source code but is not displayed as normal page content.

---

### 8. Why Use Comments?

Comments can be useful for:

* Explaining complicated code.
* Identifying different sections.
* Leaving notes for yourself.
* Helping other developers understand the code.
* Temporarily disabling HTML code during development.

For example:

```html
<!-- Student information section -->

<h2>Student Profile</h2>
<p>Name: Mohammed</p>
```

The comment tells the developer what the following section is about.

---

### 9. Comments Can Be Used to Organize Large Pages

Imagine a webpage contains many sections.

Comments can make the source code easier to navigate:

```html
<!-- Header -->
<header>
    <h1>ABC Polytechnic</h1>
</header>

<!-- Main Content -->
<main>
    <h2>Departments</h2>
    <p>Computer Engineering</p>
</main>

<!-- Footer -->
<footer>
    <p>Copyright 2026</p>
</footer>
```

The comments act like labels for the different sections.

---

### 10. Temporarily Hiding HTML Code

During development, a comment can be used to temporarily prevent a piece of HTML from being displayed.

For example:

```html
<h1>Welcome to CODIFY</h1>

<!--
<p>This section is temporarily disabled.</p>
-->
```

The paragraph inside the comment will not be rendered as normal webpage content.

This can be useful while testing different versions of a page.

> **Important:** Comments are not a security mechanism. Information placed inside HTML comments can still be seen by someone who views the page source.

---

### 11. Comments Can Be Written on One or Multiple Lines

A short comment can be written on one line:

```html
<!-- Main heading -->
```

A longer comment can use multiple lines:

```html
<!--
    This section contains
    information about
    our HTML course.
-->
```

Both use the same comment syntax.

---

### 12. Comments Do Not Appear on the Webpage

Consider:

```html
<h1>My College</h1>

<!-- This is a private note for the developer -->

<p>Welcome to our college website.</p>
```

The browser displays:

```text
My College

Welcome to our college website.
```

The comment is not displayed as webpage content.

However, the comment is still part of the HTML source.

---

### 13. Formatting vs Comments

Formatting and comments have different purposes.

| Feature                   | Purpose                     |
| :------------------------ | :-------------------------- |
| **Indentation**           | Shows code structure        |
| **Blank lines**           | Separates sections visually |
| **Comments**              | Adds notes or explanations  |
| **Consistent formatting** | Makes code easier to read   |

For example:

```html
<!-- Course information -->

<section>
    <h2>HTML Course</h2>

    <p>Learn HTML from the basics.</p>
</section>
```

Here, indentation formats the code and the comment explains the section.

---

### 14. Real-World Example

Imagine you are developing a **college website** with several sections.

You could organize your code like this:

```html
<!-- College Header -->
<header>
    <h1>ABC Polytechnic</h1>
</header>

<!-- Department Information -->
<section>
    <h2>Departments</h2>

    <p>Computer Engineering</p>
    <p>Electronics Engineering</p>
    <p>Mechanical Engineering</p>
</section>

<!-- Contact Information -->
<footer>
    <p>Contact: college@example.com</p>
</footer>
```

The comments make the different parts of the webpage easier to identify.

The indentation shows which elements belong to each section.

---

### 15. Good Formatting Practices

When writing HTML, try to follow these practices:

* Use consistent indentation.
* Keep related elements together.
* Use blank lines to separate major sections.
* Use meaningful comments when they are helpful.
* Keep comments short and useful.
* Avoid unnecessary comments for obvious code.
* Keep your source code easy to scan.

For example:

```html
<!-- Student Information -->
<section>
    <h2>Student Profile</h2>

    <p>Name: Mohammed</p>
    <p>Course: Computer Engineering</p>
</section>
```

This is easier to maintain than a large block of poorly formatted code.

---

## Key Points

* **Code formatting** makes HTML easier to read and maintain.
* **Indentation** shows the relationship between nested elements.
* Consistent formatting makes large HTML documents easier to understand.
* Blank lines can separate different sections of source code.
* HTML comments use `<!-- comment -->`.
* Comments are not normally displayed as webpage content.
* Comments can explain sections or temporarily disable code.
* Comments should be useful and not unnecessarily repeated.
* HTML comments are visible in the page source, so they should not contain sensitive information.
