# Chapter 7: HTML Tables

## Section 4: Accessibility in Tables

HTML tables are useful for displaying structured information such as student results, timetables, prices, and reports.

But a table should not only look good. It should also be **understandable to people using assistive technologies**, such as screen readers.

Accessibility means making websites easier to use for **everyone**, including people with disabilities.

> **Simple idea:** An accessible table clearly tells users what the table contains and how its data is related.

---

## 1. Why Table Accessibility Matters

Imagine a student using a screen reader.

A visual user can look at this table:

```text id="3y7m6w"
Name       | Subject | Marks
Owais      | HTML    | 95
Ahmed      | HTML    | 88
```

A screen reader cannot simply rely on the visual appearance of borders and positions.

The HTML structure should provide meaningful information about:

* What the table is about
* Which cells are headings
* Which data belongs to which heading
* What each section represents

Good HTML structure makes this information easier to understand.

---

## 2. Use `<th>` for Table Headers

One of the most important accessibility practices is using `<th>` for header cells.

Correct:

```html id="b8lj47"
<table>

    <tr>
        <th>Name</th>
        <th>Subject</th>
        <th>Marks</th>
    </tr>

    <tr>
        <td>Owais</td>
        <td>HTML</td>
        <td>95</td>
    </tr>

</table>
```

Here:

```text id="x6x0zq"
<th> → Header
<td> → Data
```

The browser and assistive technologies can understand that `Name`, `Subject`, and `Marks` are headings.

---

## 3. Do Not Use `<td>` for Headers

Avoid creating headings like this:

```html id="8vzh8u"
<tr>
    <td>Name</td>
    <td>Subject</td>
    <td>Marks</td>
</tr>
```

Although this may look like a heading visually after CSS styling, the HTML does not identify these cells as table headers.

Prefer:

```html id="p7v7bd"
<tr>
    <th>Name</th>
    <th>Subject</th>
    <th>Marks</th>
</tr>
```

Semantic HTML provides meaning, not just appearance.

---

## 4. Use `<caption>` to Describe the Table

The `<caption>` element provides a title or description for a table.

Example:

```html id="x9z8r1"
<table>

    <caption>Student Examination Results</caption>

    <tr>
        <th>Name</th>
        <th>Subject</th>
        <th>Marks</th>
    </tr>

    <tr>
        <td>Owais</td>
        <td>HTML</td>
        <td>95</td>
    </tr>

</table>
```

The caption helps users understand what the table represents.

Instead of seeing an unexplained collection of numbers and words, the user knows that the table contains **student examination results**.

---

## 5. Use Semantic Table Sections

For larger tables, use:

```html id="yqg3p6"
<thead>
<tbody>
<tfoot>
```

Example:

```html id="9h9x4c"
<table>

    <caption>Student Results</caption>

    <thead>
        <tr>
            <th>Name</th>
            <th>Marks</th>
        </tr>
    </thead>

    <tbody>
        <tr>
            <td>Owais</td>
            <td>95</td>
        </tr>

        <tr>
            <td>Ahmed</td>
            <td>88</td>
        </tr>
    </tbody>

    <tfoot>
        <tr>
            <td>Total Students</td>
            <td>2</td>
        </tr>
    </tfoot>

</table>
```

These sections make the structure easier to understand.

---

## 6. Use the `scope` Attribute

The `scope` attribute can tell the browser which cells a table header applies to.

For example:

```html id="m9h8h3"
<th scope="col">Name</th>
<th scope="col">Subject</th>
<th scope="col">Marks</th>
```

Here:

```text id="x4zq7r"
scope="col"
```

means the header applies to a **column**.

This can help assistive technologies understand the relationship between headers and data cells.

---

## 7. `scope="col"`

Use `scope="col"` when a header describes a column.

Example:

```html id="m8w8fv"
<table>

    <tr>
        <th scope="col">Name</th>
        <th scope="col">Department</th>
        <th scope="col">Marks</th>
    </tr>

    <tr>
        <td>Owais</td>
        <td>CME</td>
        <td>95</td>
    </tr>

</table>
```

Conceptually:

```text id="6m7p6a"
Name       → column heading
Department → column heading
Marks      → column heading
```

---

## 8. `scope="row"`

Sometimes a heading describes a row instead of a column.

For example:

```html id="i5h7df"
<table>

    <tr>
        <th scope="col">Student</th>
        <th scope="col">HTML</th>
        <th scope="col">DBMS</th>
    </tr>

    <tr>
        <th scope="row">Owais</th>
        <td>95</td>
        <td>92</td>
    </tr>

    <tr>
        <th scope="row">Ahmed</th>
        <td>88</td>
        <td>90</td>
    </tr>

</table>
```

Here:

```text id="q9k39p"
scope="col" → header describes a column
scope="row" → header describes a row
```

---

## 9. Understanding `scope`

Think of a table like this:

```text id="3bqvlk"
          HTML    DBMS
          ↓       ↓
Owais  →  95      92
Ahmed  →  88      90
```

The top headings describe columns.

The names on the left describe rows.

So:

```text id="y2rj8m"
<th scope="col">HTML</th>
```

means HTML is a column heading.

And:

```html id="3nkjgu"
<th scope="row">Owais</th>
```

means Owais is a row heading.

---

## 10. Real-World Example: Student Results

A more accessible result table could be:

```html id="5fjqpl"
<table>

    <caption>Student Examination Results</caption>

    <thead>
        <tr>
            <th scope="col">Student</th>
            <th scope="col">HTML</th>
            <th scope="col">DBMS</th>
            <th scope="col">Total</th>
        </tr>
    </thead>

    <tbody>
        <tr>
            <th scope="row">Owais</th>
            <td>95</td>
            <td>92</td>
            <td>187</td>
        </tr>

        <tr>
            <th scope="row">Ahmed</th>
            <td>88</td>
            <td>90</td>
            <td>178</td>
        </tr>
    </tbody>

</table>
```

Here the HTML clearly identifies:

* The table's purpose
* Column headings
* Row headings
* Student data

---

## 11. Why Use Row Headers?

Consider:

```text id="3jjh1d"
Student | HTML | DBMS
Owais   | 95   | 92
Ahmed   | 88   | 90
```

`Owais` and `Ahmed` identify the rows.

Using:

```html id="d7xj5p"
<th scope="row">Owais</th>
```

makes that relationship explicit.

This can help assistive technologies communicate the table more clearly.

---

## 12. Avoid Unnecessary Complex Tables

Simple tables are generally easier to understand.

For example:

```text id="2imxgr"
Name | Subject | Marks
```

is easier to understand than a table with many merged cells and complicated relationships.

When designing a table, ask:

> Can this information be presented in a simpler structure?

If yes, a simpler table is often easier for everyone.

---

## 13. Be Careful With `colspan` and `rowspan`

Cell merging can make tables more complicated.

For example:

```html id="9z1n5b"
<th colspan="3">Student Results</th>
```

or:

```html id="v7r9dj"
<th rowspan="2">Student</th>
```

These are useful when the structure genuinely requires them.

However, excessive merging can make relationships harder to understand.

Use `colspan` and `rowspan` only when they represent a meaningful relationship.

---

## 14. Example of a Complex Table

Consider:

```text id="6s9h5m"
+-------------------------------+
|       Examination Results     |
+----------+-------+------------+
| Student  | HTML  | DBMS       |
+----------+-------+------------+
| Owais    |  95   | 92         |
+----------+-------+------------+
```

The structure can be represented clearly using:

* `<caption>`
* `<thead>`
* `<tbody>`
* `<th>`
* `<td>`
* `scope`

Example:

```html id="3cz6c6"
<table>

    <caption>Examination Results</caption>

    <thead>
        <tr>
            <th scope="col">Student</th>
            <th scope="col">HTML</th>
            <th scope="col">DBMS</th>
        </tr>
    </thead>

    <tbody>
        <tr>
            <th scope="row">Owais</th>
            <td>95</td>
            <td>92</td>
        </tr>
    </tbody>

</table>
```

---

## 15. Do Not Depend Only on Visual Styling

Suppose CSS makes a cell bold:

```css id="7q3j8c"
.header {
    font-weight: bold;
}
```

and HTML contains:

```html id="l2h7w8"
<td class="header">Name</td>
```

It may look like a header visually.

But the HTML still says it is a normal data cell.

A better approach is:

```html id="v6j6jb"
<th scope="col">Name</th>
```

The semantic element communicates the meaning directly.

> **Important:** Accessibility should be built into the HTML structure, not added only through visual styling.

---

## 16. Accessible Table With Semantic Sections

Here is a complete example:

```html id="i2j9yq"
<table>

    <caption>Monthly Sales Report</caption>

    <thead>
        <tr>
            <th scope="col">Product</th>
            <th scope="col">Quantity</th>
            <th scope="col">Price</th>
        </tr>
    </thead>

    <tbody>
        <tr>
            <th scope="row">Keyboard</th>
            <td>10</td>
            <td>₹15,000</td>
        </tr>

        <tr>
            <th scope="row">Mouse</th>
            <td>20</td>
            <td>₹16,000</td>
        </tr>
    </tbody>

    <tfoot>
        <tr>
            <th scope="row">Total</th>
            <td>30</td>
            <td>₹31,000</td>
        </tr>
    </tfoot>

</table>
```

This table has:

```text id="qgkj2h"
<caption> → Table description
<thead>   → Header section
<th>      → Header cells
scope     → Header relationships
<tbody>   → Main data
<tfoot>   → Summary
```

---

## 17. Accessibility and Screen Readers

A screen reader can interpret semantic HTML and communicate information to the user.

For example, when a user navigates through a properly structured table, the relationship between:

```text id="7y3k9s"
Student → Owais
Subject → HTML
Marks   → 95
```

can be understood from the HTML structure.

This is why semantic table markup is important.

---

## 18. Keep Table Headings Clear

Use meaningful headings.

Good:

```html id="9y3jlh"
<th scope="col">Product Name</th>
<th scope="col">Price</th>
<th scope="col">Available Stock</th>
```

Less useful:

```html id="e8f5mq"
<th scope="col">Info</th>
<th scope="col">Data</th>
<th scope="col">Value</th>
```

Clear headings help users understand the table quickly.

## 19. Real-World Example: College Timetable

```html id="b7ypj9"
<table>

    <caption>Class Timetable</caption>

    <thead>
        <tr>
            <th scope="col">Day</th>
            <th scope="col">9:00 AM</th>
            <th scope="col">10:00 AM</th>
            <th scope="col">11:00 AM</th>
        </tr>
    </thead>

    <tbody>
        <tr>
            <th scope="row">Monday</th>
            <td>Maths</td>
            <td>HTML</td>
            <td>DBMS</td>
        </tr>

        <tr>
            <th scope="row">Tuesday</th>
            <td>C</td>
            <td>Physics</td>
            <td>HTML</td>
        </tr>
    </tbody>

</table>
```

Here:

* Days are row headings.
* Times are column headings.
* Subjects are data.
* The caption describes the table.

## 20. Common Mistakes

### Mistake 1: Using `<td>` for headings

Avoid:

```html id="u2m4fz"
<td>Name</td>
<td>Marks</td>
```

Prefer:

```html id="v3d6kq"
<th scope="col">Name</th>
<th scope="col">Marks</th>
```

---

### Mistake 2: Using an image of a table

Avoid creating important tabular information only as an image.

For example:

```text id="x5d3k8"
[Image containing student marks]
```

A real HTML table provides actual structured information that can be interpreted by browsers and assistive technologies.

Prefer real HTML:

```html id="l4k3j8"
<table>
    ...
</table>
```

---

### Mistake 3: Using tables only for visual layout

Do not use tables simply to position:

* Logos
* Navigation
* Page sections
* General website layout

Use CSS layout tools such as Flexbox and Grid for page layout.

Tables are intended for **tabular data**.

---

### Mistake 4: Using unclear headings

Avoid:

```html id="m7c9kp"
<th>Data</th>
<th>Info</th>
<th>Value</th>
```

when more meaningful headings are possible.

Prefer:

```html id="7r0e7b"
<th scope="col">Product</th>
<th scope="col">Quantity</th>
<th scope="col">Price</th>
```

---

## 21. Accessibility Checklist

Before finishing a table, check:

```text
✓ Does the table have a clear purpose?
✓ Is <caption> useful for this table?
✓ Are column headings using <th>?
✓ Are row headings using <th> when appropriate?
✓ Is scope used where it helps clarify relationships?
✓ Are <thead>, <tbody>, and <tfoot> used for larger tables?
✓ Are colspan and rowspan really necessary?
✓ Are the headings meaningful?
✓ Is the table being used for actual tabular data?
```

## 22. Quick Reference

| HTML Feature  | Purpose                   |
| :------------ | :------------------------ |
| `<caption>`   | Describes the table       |
| `<th>`        | Defines a header cell     |
| `scope="col"` | Header describes a column |
| `scope="row"` | Header describes a row    |
| `<thead>`     | Header section            |
| `<tbody>`     | Main data section         |
| `<tfoot>`     | Footer/summary section    |
| `<td>`        | Data cell                 |
| `colspan`     | Spans multiple columns    |
| `rowspan`     | Spans multiple rows       |


Then remember:

```text id="c3j1u8"

```

---

## Key Points

* Accessibility makes tables easier to understand for all users.
* Use `<th>` for table headings.
* Use `<td>` for normal data cells.
* Use `<caption>` to describe the purpose of a table.
* Use `scope="col"` for column headings.
* Use `scope="row"` for row headings.
* `<thead>`, `<tbody>`, and `<tfoot>` provide meaningful table structure.
* Use clear and descriptive headings.
* Avoid using tables for general webpage layout.
* Avoid unnecessarily complicated tables.
* Use `colspan` and `rowspan` only when they represent meaningful relationships.
* Semantic HTML is more useful than relying only on visual styling.
* Proper table structure can help screen readers and other assistive technologies understand relationships between headings and data.
