# Chapter 10: CSS & JavaScript Basics

## Section 3: Validation & Debugging

Writing HTML, CSS, and JavaScript does not always produce a perfect webpage on the first attempt.

You may make mistakes such as:

* Missing a closing tag
* Typing an incorrect attribute
* Using the wrong file path
* Writing invalid CSS
* Making a JavaScript syntax error
* Using an element incorrectly

Two important skills help us find these problems:

```text
Validation
    ↓
Checking whether code follows the expected rules

Debugging
    ↓
Finding and fixing problems in code
```

Learning how to validate and debug is an important part of web development.

---

# 1. What Is Validation?

**Validation** means checking whether your HTML or other web code follows the rules of the language.

For example:

```html
<h1>Welcome</h1>
```

is correctly structured.

But:

```html
<h1>Welcome
```

has a missing closing tag.

A validator can help identify problems like this.

---

# 2. Why Is Validation Important?

Validation can help you:

* Find errors
* Identify incorrect HTML
* Detect missing or incorrectly used elements
* Improve code quality
* Understand problems before they become difficult to find
* Follow web standards more closely

Validation is especially useful when a webpage is not behaving as expected.

---

# 3. HTML Validation

HTML can be checked using an HTML validator.

A validator examines your HTML and reports problems.

For example:

```html
<!DOCTYPE html>

<html>
<head>
    <title>My Page</title>
</head>

<body>

    <h1>Welcome</h1>
    <p>This is my webpage.</p>

</body>
</html>
```

A validator can check whether the document follows HTML rules.

---

# 4. Common HTML Problems

Some common HTML mistakes include:

```text
- Missing closing tags
- Incorrect nesting
- Invalid attributes
- Misspelled element names
- Missing required information
- Incorrect document structure
```

For example:

```html
<p>
    <strong>Hello</p>
</strong>
```

The elements are incorrectly nested.

A better structure is:

```html
<p>
    <strong>Hello</strong>
</p>
```

---

# 5. Validation Does Not Mean Your Page Is Perfect

Passing validation does not guarantee that a webpage is:

* Beautiful
* Easy to use
* Accessible in every situation
* Free from JavaScript bugs
* Perfectly designed

Validation mainly checks whether the code follows the relevant rules.

For example, valid HTML can still have poor design.

```html
<h1>My Website</h1>
```

may be valid HTML, but validation does not decide whether the heading has good colors, spacing, or layout.

---

# 6. HTML Validator

One commonly used tool for HTML validation is the **W3C Markup Validation Service**.

You can provide HTML to the validator and examine the reported messages.

The validator can help identify issues such as:

```text
Error
Warning
Invalid attribute
Incorrect structure
```

Validation tools are useful during development and learning.

---

# 7. What Is Debugging?

**Debugging** is the process of finding and fixing problems in your code.

For example:

```javascript
let number = 10;

console.log(numbber);
```

The variable was written as:

```text
number
```

but later used as:

```text
numbber
```

Debugging helps us find this mistake.

---

# 8. Validation vs Debugging

These concepts are related but different.

| Validation                                   | Debugging                                 |
| -------------------------------------------- | ----------------------------------------- |
| Checks whether code follows rules            | Finds and fixes problems                  |
| Often identifies invalid syntax or structure | Investigates why something is not working |
| Commonly uses validators                     | Commonly uses browser developer tools     |
| Often focuses on standards                   | Focuses on program behavior and errors    |

Think of it like this:

```text
Validation
↓
"Is my code written according to the rules?"

Debugging
↓
"Why isn't my code working as expected?"
```

---

# 9. Browser Developer Tools

Modern browsers provide **Developer Tools**.

They can help you inspect and debug webpages.

Common tools include:

```text
Elements
Console
Network
Sources
Application
```

The exact names and features can vary between browsers.

---

# 10. Opening Developer Tools

In many desktop browsers, Developer Tools can be opened using:

```text
F12
```

or:

```text
Ctrl + Shift + I
```

You can also usually open them through the browser's menu.

Developer Tools are extremely useful when building websites.

---

# 11. The Elements Panel

The **Elements** panel allows you to inspect the HTML structure of the current webpage.

For example:

```html
<h1 id="title">Welcome</h1>
```

You can inspect the element and see how it appears in the document.

You can also temporarily change HTML or CSS in Developer Tools to test ideas.

---

# 12. Inspecting CSS

Suppose you have:

```html
<h1 class="title">Welcome</h1>
```

and:

```css
.title {
    color: blue;
}
```

The Elements panel can show the CSS rules applied to the element.

You can temporarily change:

```css
color: blue;
```

to:

```css
color: red;
```

inside Developer Tools.

This lets you test the effect immediately.

Remember:

> Changes made directly in Developer Tools are normally temporary and do not automatically modify your source files.

---

# 13. The Console

The **Console** is one of the most useful debugging tools.

It can display:

* JavaScript errors
* Warnings
* Messages
* Debugging output

For example:

```javascript
console.log("Hello");
```

The message appears in the browser console.

---

# 14. Using `console.log()`

`console.log()` is commonly used to inspect values while debugging.

Example:

```javascript
let name = "Owais";

console.log(name);
```

The console displays:

```text
Owais
```

You can also log numbers:

```javascript
let total = 50;

console.log(total);
```

This helps you check whether a variable contains the value you expect.

---

# 15. Debugging a Calculation

Suppose you have:

```javascript
let a = 10;
let b = 20;

let result = a + b;

console.log(result);
```

The console should show:

```text
30
```

If you receive an unexpected value, you can print intermediate values:

```javascript
console.log(a);
console.log(b);
console.log(result);
```

This helps locate where the problem occurs.

---

# 16. JavaScript Errors

The browser console can show JavaScript errors.

For example:

```javascript
let name = "Owais"

console.log(username);
```

The code tries to use `username`, but that variable was not created.

The console can report an error explaining that the variable is not defined.

---

# 17. Syntax Errors

A **syntax error** occurs when code does not follow the grammar rules of the programming language.

Example:

```javascript
if (true {
    console.log("Hello");
}
```

The opening parenthesis is incorrect.

Correct:

```javascript
if (true) {
    console.log("Hello");
}
```

The browser console can help identify the location of syntax errors.

---

# 18. Runtime Errors

A **runtime error** occurs while the program is running.

Example:

```javascript
let user;

console.log(user.name);
```

Here, `user` does not contain an object that has a `name` property.

The browser can report an error when this code executes.

---

# 19. Logical Errors

A logical error is different.

The code may run without a syntax error, but it produces the wrong result.

Example:

```javascript
let price = 100;
let discount = 10;

let finalPrice = price + discount;

console.log(finalPrice);
```

The code can run, but if the intention was to subtract the discount, the logic is incorrect.

The expected calculation would be:

```javascript
let finalPrice = price - discount;
```

Debugging helps identify these kinds of problems.

---

# 20. Three Common Types of JavaScript Problems

```text
Syntax Error
↓
Code does not follow JavaScript syntax

Runtime Error
↓
Problem occurs while the program runs

Logical Error
↓
Program runs but produces an incorrect result
```

Understanding these differences makes debugging easier.

---

# 21. Reading Error Messages

When the browser displays an error, do not immediately ignore it.

Read the message carefully.

For example:

```text
ReferenceError: username is not defined
```

This tells you:

```text
Error type → ReferenceError
Problem → username is not defined
```

Error messages often provide useful clues.

---

# 22. Check the Line Number

Developer Tools often show the file and line number where an error occurred.

For example:

```text
script.js:15
```

This means the browser identified the problem around line 15 of `script.js`.

Go to that location and inspect the surrounding code.

---

# 23. File Path Debugging

Sometimes JavaScript or CSS does not work because the browser cannot find the file.

Suppose the project is:

```text
website/
│
├── index.html
└── js/
    └── script.js
```

The correct connection is:

```html
<script src="js/script.js"></script>
```

If you write:

```html
<script src="script.js"></script>
```

the browser may fail to load the file.

The **Network** panel can help you investigate resource-loading problems.

---

# 24. Network Panel

The **Network** panel can show resources requested by the webpage.

It can help you investigate:

* CSS files
* JavaScript files
* Images
* Fonts
* Other network requests

For example, if `script.js` cannot be found, you may see a failed request.

This can help identify an incorrect file path.

---

# 25. Checking a Missing CSS File

Suppose you have:

```html
<link rel="stylesheet" href="styles.css">
```

but your actual file is:

```text
style.css
```

The names are different.

The stylesheet will not load correctly.

Check:

```text
HTML filename
       ↓
styles.css

Actual filename
       ↓
style.css
```

Fix the path:

```html
<link rel="stylesheet" href="style.css">
```

---

# 26. Debugging Step by Step

When something does not work, use a systematic approach.

### Step 1: Reproduce the Problem

Find exactly what is not working.

### Step 2: Check the Console

Look for JavaScript errors or warnings.

### Step 3: Inspect the HTML

Use the Elements panel.

### Step 4: Check CSS

Look at the styles applied to the element.

### Step 5: Check File Paths

Make sure CSS, JavaScript, images, and other files are correctly linked.

### Step 6: Check the Code

Look for spelling mistakes, missing characters, and incorrect logic.

### Step 7: Test Again

After making a change, reload the page and check whether the problem is fixed.

---

# 27. Use Small Tests

When debugging, avoid changing many things at once.

For example, if this does not work:

```javascript
let result = calculateTotal(price, tax, discount);
```

test the individual values:

```javascript
console.log(price);
console.log(tax);
console.log(discount);
```

Then check the function.

Small tests make problems easier to locate.

---

# 28. Use Meaningful Console Messages

Instead of:

```javascript
console.log(x);
```

you can write:

```javascript
console.log("Total price:", x);
```

This makes the output easier to understand.

Example:

```javascript
let price = 500;
let quantity = 3;

let total = price * quantity;

console.log("Price:", price);
console.log("Quantity:", quantity);
console.log("Total:", total);
```

The console output clearly shows what each value means.

---

# 29. Browser Cache and Debugging

Sometimes you may change a file but still see an older version.

This can happen because browsers can cache resources.

If a change does not appear:

```text
1. Reload the page
2. Check that you edited the correct file
3. Check the file path
4. Use a hard reload if necessary
```

Do not assume that every problem is caused by caching.

Check the source files and Developer Tools first.

---

# 30. Validation and Accessibility

Validation and accessibility are related but not identical.

Valid HTML does not automatically mean that a page is fully accessible.

For example:

```html
<img src="logo.png">
```

may require meaningful alternative text depending on the image's purpose.

A better example for a meaningful image is:

```html
<img src="college.jpg"
     alt="Main building of the college">
```

Accessibility requires thinking about how different users interact with the page.

---

# 31. Common Debugging Mistakes

### Mistake 1: Ignoring the Console

If JavaScript does not work, always check the Console.

---

### Mistake 2: Looking Only at the Last Line

An error may be caused by code earlier in the file.

Check the surrounding code as well.

---

### Mistake 3: Changing Everything at Once

If you change ten things, you may not know which change fixed or caused the problem.

Make one change at a time when possible.

---

### Mistake 4: Ignoring File Paths

Always check:

```text
Filename
Folder
Extension
Relative path
```

---

### Mistake 5: Assuming Every Error Is a Syntax Error

Some programs have valid syntax but incorrect logic.

Remember:

```text
Syntax
Runtime
Logic
```

are different kinds of problems.

---

# 32. Practical Example

Suppose you have:

### `index.html`

```html
<!DOCTYPE html>
<html>

<head>
    <title>Debugging Example</title>
</head>

<body>

    <h1 id="title">Hello</h1>

    <button id="changeButton">
        Change Text
    </button>

    <script src="script.js"></script>

</body>

</html>
```

### `script.js`

```javascript
document.getElementById("changeButton")
    .addEventListener("click", function () {

        document.getElementById("title").textContent =
            "Welcome!";

    });
```

If the button does not work:

```text
1. Open Developer Tools
2. Open Console
3. Check for errors
4. Check whether script.js loaded
5. Check the element IDs
6. Check the JavaScript syntax
7. Reload the page
```

This is a simple debugging workflow.

---

# 33. Practical Debugging Checklist

When your webpage has a problem, check:

```text
□ Is the HTML valid?
□ Are tags correctly nested?
□ Are filenames correct?
□ Are file paths correct?
□ Is the CSS file loading?
□ Is the JavaScript file loading?
□ Is there an error in the Console?
□ Are element IDs spelled correctly?
□ Are variables spelled correctly?
□ Is the program logic correct?
□ Did you test the change again?
```

---

# 35. Key Points

* Validation checks whether code follows relevant rules and standards.
* Debugging is the process of finding and fixing problems.
* HTML validators can identify problems in HTML structure.
* Passing validation does not guarantee perfect design or accessibility.
* Developer Tools are useful for investigating webpage problems.
* The Elements panel helps inspect HTML and CSS.
* The Console helps identify JavaScript errors and display debugging information.
* `console.log()` is useful for checking values.
* The Network panel can help identify resource-loading problems.
* Syntax errors occur when code does not follow language syntax.
* Runtime errors occur while code is running.
* Logical errors occur when code runs but produces the wrong result.
* File paths and filenames should always be checked when resources fail to load.
* Debug problems systematically instead of changing everything at once.
* Validation and debugging are different skills, but both are important in web development.
