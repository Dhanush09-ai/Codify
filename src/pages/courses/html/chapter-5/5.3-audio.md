# Chapter 5: Images & Media

## Section 3: Audio Elements

Webpages can contain more than text and images. HTML also allows you to add **audio** such as music, voice recordings, podcasts, sound effects, and pronunciation examples.

HTML provides the `<audio>` element for adding audio content to a webpage.

> **Simple idea:** Use `<audio>` when you want users to listen to sound directly from your webpage.

---

## 1. The `<audio>` Element

The basic syntax is:

```html
<audio controls>
    <source src="audio.mp3" type="audio/mpeg">
</audio>
```

The `<audio>` element creates an audio player.

The `controls` attribute tells the browser to display controls such as:

* Play
* Pause
* Volume
* Progress bar

---

## 2. A Simple Audio Example

```html
<audio controls>
    <source src="song.mp3" type="audio/mpeg">
</audio>
```

If the browser supports the audio format, the user can play the file using the displayed controls.

---

## 3. The `controls` Attribute

Without `controls`:

```html
<audio src="song.mp3"></audio>
```

the browser may not provide visible controls.

With:

```html
<audio controls src="song.mp3"></audio>
```

the browser displays its built-in audio controls.

For most normal audio players, you should provide controls so users can control playback.

---

## 4. Using the `src` Attribute

You can specify an audio file directly using `src`.

Example:

```html
<audio
    controls
    src="audio/lesson.mp3"
>
</audio>
```

Here:

```text
audio/lesson.mp3
```

is the path to the audio file.

Just like images, the path can be:

* Relative
* Absolute

---

## 5. Using `<source>`

A more flexible approach is to use one or more `<source>` elements inside `<audio>`.

Example:

```html
<audio controls>
    <source src="lesson.mp3" type="audio/mpeg">
</audio>
```

The `<source>` element provides the audio file and its MIME type.

---

## 6. Why Use `<source>`?

Different browsers and devices can have different levels of support for media formats.

You can provide multiple sources:

```html
<audio controls>
    <source src="lesson.mp3" type="audio/mpeg">
    <source src="lesson.ogg" type="audio/ogg">
</audio>
```

The browser can use a source it supports.

> **Simple idea:** Multiple `<source>` elements can provide fallback audio formats.

---

## 7. Common Audio Formats

Some common audio formats used on the web include:

* MP3
* Ogg
* WAV

### MP3

MP3 is widely supported and commonly used for:

* Music
* Voice recordings
* Podcasts
* Online lessons

Example:

```html
<audio controls>
    <source src="lesson.mp3" type="audio/mpeg">
</audio>
```

### Ogg

Ogg can also be used for web audio.

```html
<audio controls>
    <source src="lesson.ogg" type="audio/ogg">
</audio>
```

### WAV

WAV can provide high-quality audio but often produces larger files.

```html
<audio controls>
    <source src="sound.wav" type="audio/wav">
</audio>
```

---

## 8. Audio Format Comparison

| Format | Common Use              | File Size       |
| :----- | :---------------------- | :-------------- |
| MP3    | Music, speech, podcasts | Usually smaller |
| Ogg    | Web audio               | Often efficient |
| WAV    | High-quality audio      | Usually larger  |

The best format depends on the project's requirements.

---

## 9. The `type` Attribute

The `type` attribute tells the browser what type of audio file is being provided.

Example:

```html
<source
    src="lesson.mp3"
    type="audio/mpeg"
>
```

For Ogg:

```html
<source
    src="lesson.ogg"
    type="audio/ogg"
>
```

For WAV:

```html
<source
    src="lesson.wav"
    type="audio/wav"
>
```

Providing the correct MIME type helps the browser understand the source.

---

## 10. Fallback Text

You can place text inside the `<audio>` element.

Example:

```html
<audio controls>
    <source src="lesson.mp3" type="audio/mpeg">

    Your browser does not support HTML audio.
</audio>
```

The text can act as fallback content if the browser cannot use the audio element.

---

## 11. Complete Basic Example

```html
<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="UTF-8">
    <title>Audio Example</title>
</head>

<body>

    <h1>Listen to the Lesson</h1>

    <audio controls>
        <source src="audio/lesson.mp3" type="audio/mpeg">

        Your browser does not support HTML audio.
    </audio>

</body>

</html>
```

This creates a webpage with a built-in audio player.

---

## 12. The `autoplay` Attribute

The `autoplay` attribute asks the browser to start playing the audio automatically.

Example:

```html
<audio controls autoplay>
    <source src="intro.mp3" type="audio/mpeg">
</audio>
```

However, modern browsers often restrict autoplay, especially when audio would play with sound without user interaction.

Because unexpected sound can be annoying, avoid using autoplay unless there is a clear reason.

---

## 13. The `loop` Attribute

The `loop` attribute makes the audio start again after it finishes.

Example:

```html
<audio controls loop>
    <source src="background.mp3" type="audio/mpeg">
</audio>
```

This can be useful for audio that is intentionally repeated.

---

## 14. The `muted` Attribute

The `muted` attribute starts the audio in a muted state.

Example:

```html
<audio controls muted>
    <source src="intro.mp3" type="audio/mpeg">
</audio>
```

The user can usually unmute it using the audio controls.

---

## 15. Combining Audio Attributes

Multiple attributes can be used together.

Example:

```html
<audio controls loop muted>
    <source src="background.mp3" type="audio/mpeg">
</audio>
```

This provides:

* Audio controls
* Repeated playback
* Muted initial state

Use these attributes according to the purpose of the audio.

---

## 16. The `preload` Attribute

The `preload` attribute provides a hint about how the browser should load audio.

Common values include:

```text
none
metadata
auto
```

### `none`

```html
<audio controls preload="none">
```

The browser is told not to preload the audio.

### `metadata`

```html
<audio controls preload="metadata">
```

The browser may load information such as the duration without downloading the entire audio file.

### `auto`

```html
<audio controls preload="auto">
```

The browser may preload more of the audio.

> **Important:** `preload` is a hint. The browser can decide how much data to actually load.

---

## 17. Choosing a Preload Value

For a page containing many large audio files, loading everything immediately can use unnecessary bandwidth.

For example:

```html
<audio controls preload="none">
    <source src="large-podcast.mp3" type="audio/mpeg">
</audio>
```

can tell the browser that the audio does not need to be preloaded.

For short lesson audio, another choice may be more appropriate depending on the user experience you want.

---

## 18. Audio File Paths

Audio paths work similarly to image paths.

Suppose:

```text
website/
├── index.html
└── audio/
    └── lesson.mp3
```

Use:

```html
<audio controls>
    <source src="audio/lesson.mp3" type="audio/mpeg">
</audio>
```

If the HTML file is inside another folder:

```text
website/
├── audio/
│   └── lesson.mp3
└── pages/
    └── lesson.html
```

use:

```html
<audio controls>
    <source src="../audio/lesson.mp3" type="audio/mpeg">
</audio>
```

## 19. Real-World Example: Online Course

An online HTML course can provide a spoken explanation.

```html
<section>
    <h2>Listen to the Explanation</h2>

    <audio controls>
        <source
            src="audio/html-introduction.mp3"
            type="audio/mpeg"
        >

        Your browser does not support HTML audio.
    </audio>
</section>
```

Students can read the lesson and listen to the explanation.

---

## 20. Real-World Example: Language Learning

A language-learning website can provide pronunciation audio.

```html
<p>Listen to the pronunciation:</p>

<audio controls>
    <source
        src="audio/hello.mp3"
        type="audio/mpeg"
    >
</audio>
```

This can be useful for practicing:

* Words
* Sentences
* Conversations
* Pronunciation

---

## 21. Real-World Example: Podcast

A website can embed an episode using:

```html
<article>
    <h2>Episode 1: Introduction</h2>

    <audio controls preload="metadata">
        <source
            src="audio/episode-1.mp3"
            type="audio/mpeg"
        >

        Your browser does not support HTML audio.
    </audio>
</article>
```

The user can control playback directly from the webpage.

---

## 22. Audio and Accessibility

Audio content should be presented clearly.

For important spoken information, consider providing a text transcript.

Example:

```html
<h2>Lesson Audio</h2>

<audio controls>
    <source src="lesson.mp3" type="audio/mpeg">
</audio>

<h3>Transcript</h3>

<p>
    HTML is a markup language used to structure content
    on webpages.
</p>
```

A transcript can make the information available to users who cannot listen to the audio.

---

## 23. Do Not Force Audio on Users

Unexpected audio can interrupt the user.

For example, automatically starting a loud audio clip when someone opens a webpage can create a poor experience.

It is usually better to allow the user to decide when audio starts.

A simple player with:

```html
<audio controls>
```

gives the user control over playback.

---

## 24. Audio File Size

Audio files can be large.

For example:

```text
lesson.mp3 → 3 MB
podcast.mp3 → 50 MB
```

Large files require more bandwidth and may take longer to load.

Consider:

* Appropriate audio quality
* Suitable compression
* Reasonable file size
* Streaming or external media services for very large content

Do not use unnecessarily high-quality audio when it does not improve the user's experience.

---

## 25. Keep Audio Organized

A project can store audio files in a dedicated folder.

Example:

```text
website/
├── index.html
├── css/
│   └── style.css
├── images/
│   └── logo.svg
└── audio/
    ├── introduction.mp3
    ├── lesson-1.mp3
    └── pronunciation.mp3
```

This makes the project easier to manage.

---

## 26. Use Meaningful Audio File Names

Avoid:

```text
audio1.mp3
recording2.mp3
finalnew.mp3
```

Prefer:

```text
html-introduction.mp3
lesson-1-explanation.mp3
html-pronunciation.mp3
```

Meaningful filenames make projects easier to understand.

---

## 27. Multiple Audio Sources

You can provide fallback formats.

Example:

```html
<audio controls>

    <source
        src="lesson.mp3"
        type="audio/mpeg"
    >

    <source
        src="lesson.ogg"
        type="audio/ogg"
    >

    Your browser does not support HTML audio.

```

The browser can select an appropriate source.

---

## 28. Audio vs `<embed>`

HTML provides a dedicated `<audio>` element for audio content.

Prefer:

```html
<audio controls>
    <source src="lesson.mp3" type="audio/mpeg">
</audio>
```

rather than relying on older or plugin-based approaches.

The `<audio>` element is designed specifically for audio media.

---

## 29. Complete Example

```html
<!DOCTYPE html>
<html lang="en">

<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">

    <title>HTML Audio</title>
</head>

<body>

    <h1>HTML Audio Lesson</h1>

    <p>
        Listen to the explanation below:
    </p>

    <audio controls preload="metadata">

        <source
            src="audio/html-introduction.mp3"
            type="audio/mpeg"
        >

        <source
            src="audio/html-introduction.ogg"
            type="audio/ogg"
        >

        Your browser does not support HTML audio.

    </audio>

    <h2>Transcript</h2>

    <p>
        HTML is used to structure content on webpages.
    </p>

</body>

</html>
```

This example demonstrates:

* `<audio>`
* `controls`
* `<source>`
* `type`
* Multiple audio formats
* `preload`
* Fallback text
* A transcript

## 30. Common Mistakes

### Mistake 1: Incorrect file path

```html
<audio controls>
    <source src="audio/lesson.mp3" type="audio/mpeg">
</audio>
```

Make sure the file actually exists at that location.

---

### Mistake 2: Wrong MIME type

For MP3, use:

```html
type="audio/mpeg"
```

For Ogg:

```html
type="audio/ogg"
```

The type should match the actual file format.

---

### Mistake 3: Forgetting `controls`

```html
<audio>
    <source src="lesson.mp3" type="audio/mpeg">
</audio>
```

The audio may not provide visible controls.

For a normal user-controlled player, use:

```html
<audio controls>
```

---

### Mistake 4: Automatically playing audio unnecessarily

Avoid automatically starting audio simply because the page loaded.

Users should generally have control over when audio plays.

---

## Key Points

* The `<audio>` element is used to add audio to a webpage.
* `controls` displays playback controls.
* `src` can specify an audio file directly.
* `<source>` can provide audio files and their MIME types.
* Multiple `<source>` elements can provide fallback formats.
* Common audio formats include MP3, Ogg, and WAV.
* `type` describes the MIME type of the audio source.
* `autoplay` requests automatic playback, but browsers may restrict it.
* `loop` repeats the audio.
* `muted` starts the audio muted.
* `preload` provides a hint about how audio should be loaded.
* Audio files should have reasonable file sizes.
* Meaningful filenames and organized folders make projects easier to maintain.
* Important spoken information can be accompanied by a transcript.
* Avoid unexpected audio playback.
* The `<audio>` element is the standard HTML approach for embedding audio.
