# Chapter 5: Images & Media

## Section 2: Image Types & Best Practices

Images are an important part of modern websites. But choosing the right image type and using images correctly can make a big difference in **quality, loading speed, accessibility, and user experience**.

Different image formats are designed for different purposes.

For example:

* A photograph needs a different format than a logo.
* A transparent icon needs a different format than a large photo.
* A simple vector graphic may be better as SVG than JPG.

> **Simple idea:** Choose the image format based on what the image contains and how it will be used.

---

## 1. Common Image Types

The most common image formats used on websites are:

* JPEG / JPG
* PNG
* GIF
* SVG
* WebP
* AVIF

Each format has different strengths and weaknesses.

---

## 2. JPEG / JPG

JPEG stands for **Joint Photographic Experts Group**.

It is commonly used for photographs and images containing many colors.

Example:

```html
<img src="college.jpg" alt="College building">
```

JPEG uses **lossy compression**, which means some image information can be removed to reduce file size.

### Good for:

* Photographs
* Travel pictures
* College campus photos
* Product photos
* Large colorful images

### Not ideal for:

* Simple logos
* Images requiring transparency
* Small icons
* Images containing lots of sharp text

> **Remember:** JPG is usually a good choice for photographs.

---

## 3. PNG

PNG stands for **Portable Network Graphics**.

PNG supports transparency and uses **lossless compression**.

Example:

```html
<img src="logo.png" alt="Website Logo">
```

PNG is useful when image quality and transparency are important.

### Good for:

* Logos
* Screenshots
* UI graphics
* Transparent images
* Images containing sharp text

### Example

A website logo with a transparent background can be stored as:

```text
logo.png
```

The transparent areas allow the logo to appear naturally on different backgrounds.

---

## 4. GIF

GIF stands for **Graphics Interchange Format**.

GIF supports simple animations and a limited color palette.

Example:

```html
<img src="loading.gif" alt="Loading animation">
```

GIF is commonly associated with small animated images.

### Good for:

* Simple animations
* Short looping graphics
* Small animated illustrations

### Limitations:

* Limited number of colors
* Usually not ideal for photographs
* Modern formats can often provide better compression

> **Tip:** For new projects, consider whether WebP or another modern format is more suitable for animated content.

---

## 5. SVG

SVG stands for **Scalable Vector Graphics**.

Unlike JPG, PNG, and GIF, SVG is a **vector image format**.

Example:

```html
<img src="logo.svg" alt="CODIFY Logo">
```

SVG images are based on shapes, paths, and other mathematical descriptions rather than a fixed grid of pixels.

This means an SVG can be scaled to different sizes without the same type of pixelation that can occur with raster images.

### Good for:

* Logos
* Icons
* Simple illustrations
* Diagrams
* Interface graphics

### Example

A website icon can be stored as:

```text
menu.svg
```

and displayed at different sizes.

---

## 6. WebP

WebP is a modern image format designed for efficient web delivery.

It can support:

* Lossy compression
* Lossless compression
* Transparency
* Animation

Example:

```html
<img src="course.webp" alt="HTML course illustration">
```

WebP can often provide smaller files than older formats while maintaining good visual quality.

### Good for:

* Website photos
* Course illustrations
* Product images
* General web graphics

> **Simple idea:** WebP is a useful modern format for many types of web images.

---

## 7. AVIF

AVIF is another modern image format designed for efficient compression.

Example:

```html
<img src="photo.avif" alt="Student studying">
```

It can provide strong compression while maintaining good image quality.

### Good for:

* Modern websites
* Photographs
* High-quality web images
* Performance-focused websites

However, you should consider browser support and your project's requirements before choosing a format.

---

## 8. Raster vs Vector Images

Image formats can broadly be divided into two groups.

### Raster Images

Raster images are made from pixels.

Common examples:

* JPG
* PNG
* GIF
* WebP
* AVIF

A raster image has a fixed pixel structure.

For example:

```text
1920 × 1080
```

means the image contains a grid of pixels with that width and height.

---

### Vector Images

Vector images are based on mathematical shapes.

The most common web vector format is:

```text
SVG
```

Vectors can be scaled to different sizes while maintaining sharp edges.

---

## 9. Raster vs Vector Example

Imagine a college logo.

If the logo is stored as a raster image:

```text
logo.png
```

making it extremely large can eventually make the edges look pixelated.

If the logo is stored as:

```text
logo.svg
```

it can be scaled to different sizes while maintaining its vector-based shapes.

> **Rule of thumb:** Use SVG when the graphic is naturally suited to vector shapes, such as logos and icons.

---

## 10. Image Format Comparison

| Format | Type   | Transparency | Animation | Common Use         |
| :----- | :----- | :----------- | :-------- | :----------------- |
| JPG    | Raster | No           | No        | Photographs        |
| PNG    | Raster | Yes          | No        | Logos, screenshots |
| GIF    | Raster | Yes          | Yes       | Simple animations  |
| SVG    | Vector | Yes          | Possible  | Logos, icons       |
| WebP   | Raster | Yes          | Yes       | General web images |
| AVIF   | Raster | Yes          | Yes       | Modern web images  |

The exact capabilities and browser behavior can vary by use case.

### Logo

The best choice depends on the actual image and project requirements.

## 12. Image Quality vs File Size

Images can be large files.

For example:

```text
photo-original.jpg
5 MB
```

may be unnecessarily large for a webpage.

A compressed version might be:

```text
photo-web.jpg
300 KB
```

The smaller file can load much faster while still looking good.

> **Important:** The goal is not simply to make the image as small as possible. The goal is to achieve a good balance between **quality and file size**.

---

## 13. Why Large Images Slow Down Websites

Suppose a webpage contains:

```text
Image 1 → 4 MB
Image 2 → 3 MB
Image 3 → 5 MB
Image 4 → 2 MB
```

The total is:

```text
14 MB
```

The browser may need to download a large amount of data before all images are available.

This can make the page feel slow, especially on:

* Mobile networks
* Slow internet connections
* Older devices

Reducing unnecessary image size can improve the user experience.

---

## 14. Resize Before Uploading

Suppose a website displays a banner at approximately:

```text
1200 × 400
```

There is usually little reason to upload a huge:

```text
6000 × 2000
```

image and then display it much smaller.

Instead, create an appropriately sized version.

This can reduce:

* File size
* Download time
* Bandwidth usage

---

## 15. Compress Images

Image compression reduces file size.

For example:

```text
Original image → 2.5 MB
Compressed image → 450 KB
```

If the visual difference is small, the compressed version can be more suitable for the web.

Compression can be:

* Lossy
* Lossless

---

## 16. Lossy Compression

Lossy compression removes some image information to achieve a smaller file.

This is common with formats such as JPEG.

For example:

```text
Original → 2 MB
Compressed → 500 KB
```

The image may lose some quality, depending on the compression level.

Lossy compression is often useful for photographs where a small amount of quality loss may not be noticeable.

---

## 17. Lossless Compression

Lossless compression reduces file size without permanently removing image information.

PNG commonly uses lossless compression.

This can be useful when preserving exact image information is important.

However, lossless files can sometimes be larger than equivalent lossy images.

---

## 18. Responsive Images

Different devices have different screen sizes.

A large desktop image may not always be necessary on a small mobile screen.

HTML provides tools such as `srcset` to provide different image sources.

Example:

```html
<img
    src="small.jpg"
    srcset="
        small.jpg 480w,
        medium.jpg 800w,
        large.jpg 1200w
    "
    alt="College campus"
>
```

The browser can use the available information to select an appropriate image resource.

---

## 19. Why `srcset` Is Useful

Imagine a user visiting a website from a mobile phone.

Downloading a very large image when a smaller version would be sufficient wastes:

* Data
* Time
* Bandwidth

Using multiple image sources can help browsers choose an appropriate resource.

This is especially useful for responsive websites.

---

## 20. The `sizes` Attribute

The `sizes` attribute can provide information about how much space an image is expected to occupy.

Example:

```html
<img
    src="medium.jpg"
    srcset="
        small.jpg 480w,
        medium.jpg 800w,
        large.jpg 1200w
    "
    sizes="(max-width: 600px) 100vw, 50vw"
    alt="College campus"
>
```

Here:

```text
100vw
```

means approximately the full viewport width.

And:

```text
50vw
```

means approximately half of the viewport width.

This information helps the browser select an appropriate image resource.

---

## 21. Lazy Loading

Images that are far below the visible area of a webpage may not need to load immediately.

HTML provides:

```html
<img
    src="course.jpg"
    alt="HTML course illustration"
    loading="lazy"
>
```

The browser can defer loading the image until it is closer to being needed.

This can be useful for pages containing many images.

---

## 22. When Not to Use Lazy Loading

Images that are immediately visible when the page loads may not benefit from lazy loading.

For example, the main image at the top of an article may be important to the initial page display.

Example:

```html
<img
    src="hero.jpg"
    alt="HTML course introduction"
>
```

For below-the-fold images, lazy loading can be useful:

```html
<img
    src="example.jpg"
    alt="HTML example"
    loading="lazy"
>
```

> **Simple idea:** Lazy-load images that can reasonably wait, rather than automatically applying it to every image.

---

## 23. Descriptive `alt` Text

Good image practices are not only about performance.

Accessibility is also important.

Example:

```html
<img
    src="student.jpg"
    alt="Student writing HTML code on a laptop"
>
```

The `alt` text communicates the important content of the image.

Avoid:

```html
<img src="student.jpg" alt="photo">
```

because it provides very little useful information.

---

## 24. Decorative Images

If an image is purely decorative, use an empty `alt` attribute:

```html
<img src="line-decoration.svg" alt="">
```

This prevents unnecessary image descriptions from being presented to users of assistive technologies.

Do not use:

```html
<img src="line-decoration.svg">
```

when the image should intentionally have empty alternative text.

---

## 25. Do Not Put Important Text Only Inside Images

Avoid creating an important message entirely inside an image.

For example, instead of:

```text
[IMAGE]
"Submit your application before Friday"
```

place the important information in actual HTML text when possible:

```html
<p>
    Submit your application before Friday.
</p>
```

This makes the information easier to:

* Read
* Search
* Translate
* Resize
* Access with assistive technologies

---

## 26. Use Meaningful File Names

Compare:

```text
IMG001.jpg
DSC0007.jpg
image1.png
```

with:

```text
html-structure.png
college-campus.jpg
codify-logo.svg
```

Meaningful names make projects easier to manage.

A good filename can tell you what the image contains without opening it.

---

## 27. Use Lowercase File Names

For web projects, consistent lowercase file names can reduce confusion.

Prefer:

```text
college-campus.jpg
```

instead of:

```text
College Campus.JPG
```

Also avoid unnecessary spaces and unusual characters.

Use:

```text
html-course-banner.webp
```

instead of:

```text
HTML Course Banner Final Image 2.webp
```

---

## 28. Organize Images

A website project can keep images inside a dedicated folder.

Example:

```text
website/
├── index.html
├── about.html
├── css/
│   └── style.css
└── images/
    ├── logo.svg
    ├── campus.jpg
    ├── html-course.webp
    └── icons/
        ├── menu.svg
        └── search.svg
```

This makes the project easier to maintain.

---

## 29. Avoid Unnecessarily Huge Images

Suppose an icon is displayed at:

```text
32 × 32
```

There is usually no need to use a huge photograph containing thousands of pixels for that purpose.

Choose an image appropriate for its intended display size.

This can improve performance and reduce unnecessary data transfer.

---

## 30. Keep Image Dimensions in Mind

An image can have intrinsic dimensions.

For example:

```text
1920 × 1080
```

If the browser needs to display it at:

```text
640 × 360
```

you may want to provide a suitable smaller resource when practical.

This is especially important for image-heavy websites.

---

## 31. Prevent Layout Problems

Images can affect the layout while a page is loading.

Providing width and height information can help the browser reserve space.

Example:

```html
<img
    src="campus.jpg"
    alt="College campus"
    width="1200"
    height="800"
>
```

The browser knows the image's intended dimensions and can allocate space accordingly.

CSS can still control the final displayed size.

---

## 32. Use `object-fit` When Appropriate

CSS provides `object-fit` for controlling how replaced elements such as images fit within their boxes.

Example:

```css
.card-image {
    width: 300px;
    height: 200px;
    object-fit: cover;
}
```

`cover` allows the image to fill the specified area while maintaining its aspect ratio, with some parts potentially being cropped.

Another option is:

```css
.card-image {
    object-fit: contain;
}
```

This keeps the entire image visible within the available area, potentially leaving empty space.

## 36. A Practical Image Checklist

Before adding an image to a website, ask:

### Format

* Is this a photograph?
* Is this a logo?
* Does it need transparency?
* Would SVG be appropriate?
* Would WebP or AVIF be useful?

### Size

* Is the original image unnecessarily large?
* Can it be resized?
* Can it be compressed?

### Accessibility

* Does the image need meaningful `alt` text?
* Is it purely decorative?
* Is important information being placed only inside the image?

### Performance

* Should the image use `loading="lazy"`?
* Would `srcset` help?
* Are width and height specified?

### Organization

* Is the filename meaningful?
* Is the image stored in the correct folder?

## 37. Best Practices Summary

### 1. Choose the right format

Use the format that matches the image.

```text
Photo → JPG / WebP / AVIF
Logo → SVG / PNG / WebP
Icon → SVG
Animation → GIF / WebP
```

### 2. Optimize file size

Do not upload unnecessarily huge images.

### 3. Use descriptive `alt` text

Describe the meaningful content of an image.

### 4. Use empty `alt` for decorative images

```html
alt=""
```

### 5. Use responsive images when needed

Consider `srcset` and `sizes`.

### 6. Use lazy loading appropriately

```html
loading="lazy"
```

### 7. Give images useful dimensions

Width and height information can help prevent layout shifts.

### 8. Use meaningful filenames

Prefer:

```text
html-structure.webp
```

over:

```text
IMG001.jpg
```

### 9. Keep images organized

Use folders such as:

```text
images/
```

### 10. Think about users

A good image should be:

* Useful
* Accessible
* Appropriately sized
* Fast to load
* Relevant to the content

## Key Points

* Different image formats are designed for different purposes.
* JPG is commonly used for photographs.
* PNG is useful for transparency and lossless graphics.
* GIF supports simple animation.
* SVG is a vector format useful for logos, icons, and illustrations.
* WebP and AVIF are modern formats designed for efficient web images.
* Raster images are pixel-based, while SVG is vector-based.
* Large images can slow down webpages.
* Resize and compress images when appropriate.
* `srcset` can provide multiple image resources.
* `sizes` provides information about the expected display size.
* `loading="lazy"` can defer loading of images that are not immediately needed.
* Use meaningful `alt` text for informative images.
* Use `alt=""` for decorative images.
* Do not place important information only inside an image.
* Meaningful filenames and organized folders make projects easier to maintain.
* Width and height information can help prevent layout shifts.
* Choose image formats based on the content and requirements of the website.
