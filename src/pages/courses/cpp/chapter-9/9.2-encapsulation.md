# Chapter 9: Object-Oriented Programming

## Section 2: Encapsulation

**Encapsulation** is an important concept of Object-Oriented Programming.

Encapsulation means **grouping data and the functions that operate on that data together inside a class**.

It also allows us to **control access to the data**.

In C++, encapsulation is commonly implemented using:

* Classes
* Private data members
* Public member functions
* Access specifiers

---

## 1. What is Encapsulation?

Imagine a bank account.

An account contains data such as:

```text
Account
├── account number
├── account holder
└── balance
```

It also has operations such as:

```text
deposit()
withdraw()
checkBalance()
```

Instead of keeping these separately, we can put them together inside a class.

```text
BankAccount
├── Data
│   ├── accountNumber
│   └── balance
│
└── Functions
    ├── deposit()
    ├── withdraw()
    └── checkBalance()
```

This grouping of data and related functions is called **encapsulation**.

---

## 2. Encapsulation Using a Class

A class is one of the main tools used to implement encapsulation in C++.

### Example

```cpp
#include <iostream>
using namespace std;

class Student {
private:
    int marks;

public:
    void setMarks(int value) {
        marks = value;
    }

    int getMarks() {
        return marks;
    }
};

int main() {
    Student student;

    student.setMarks(95);

    cout << student.getMarks();

    return 0;
}
```


```output
95
```

Here:

* `marks` is private.
* `setMarks()` changes the value.
* `getMarks()` reads the value.
* All of them belong to the `Student` class.

---

## 3. Data Members and Member Functions

A class can contain both data and functions.

### Data Members

Data members store information about an object.

Example:

```cpp
int marks;
string name;
```

### Member Functions

Member functions perform operations related to the object's data.

Example:

```cpp
void display();
void setMarks(int value);
```

Encapsulation keeps related data and functions together.

---

## 4. Private Members

The `private` access specifier is commonly used to protect data.

A private member cannot normally be accessed directly from outside the class.

### Example

```cpp
#include <iostream>
using namespace std;

class Student {
private:
    int marks;
};

int main() {
    Student student;

    // student.marks = 95;  // Not allowed

    return 0;
}
```

The `marks` member is private.

Therefore, code outside the class cannot directly access it.

---

## 5. Public Member Functions

Public member functions can be called from outside the class.

They can provide controlled access to private data.

### Example

```cpp
#include <iostream>
using namespace std;

class Student {
private:
    int marks;

public:
    void setMarks(int value) {
        marks = value;
    }

    int getMarks() {
        return marks;
    }
};

int main() {
    Student student;

    student.setMarks(90);

    cout << student.getMarks();

    return 0;
}
```


```output
90
```

The outside code does not access `marks` directly.

Instead, it uses the public functions.

---

## 6. Getter and Setter Functions

Two common functions used with encapsulation are:

* **Setter** — changes or sets a value.
* **Getter** — reads or gets a value.

Example:

```cpp
class Student {
private:
    int marks;

public:
    void setMarks(int value) {
        marks = value;
    }

    int getMarks() {
        return marks;
    }
};
```

Here:

```cpp
setMarks()
```

is a setter.

```cpp
getMarks()
```

is a getter.

---

## 7. Why Use Getters and Setters?

Getters and setters allow us to control how data is accessed or changed.

Without encapsulation:

```cpp
student.marks = -50;
```

could potentially put an invalid value into the object.

With a setter, we can validate the value before storing it.

### Example

```cpp
#include <iostream>
using namespace std;

class Student {
private:
    int marks;

public:
    void setMarks(int value) {
        if (value >= 0 && value <= 100) {
            marks = value;
        }
    }

    int getMarks() {
        return marks;
    }
};

int main() {
    Student student;

    student.setMarks(95);

    cout << student.getMarks();

    return 0;
}
```


```output
95
```

The setter checks whether the marks are within the valid range.

## 8. Data Hiding

Encapsulation is closely related to **data hiding**.

Data hiding means restricting direct access to the internal data of an object.

For example:

```cpp
class BankAccount {
private:
    double balance;

public:
    void deposit(double amount) {
        balance += amount;
    }
};
```

The `balance` cannot normally be changed directly from outside the class.

Instead, the class controls how it is modified.

---

## 9. Encapsulation and Access Specifiers

C++ provides three main access specifiers:

| Access Specifier | Access                                          |
| ---------------- | ----------------------------------------------- |
| `public`         | Accessible from outside the class               |
| `private`        | Accessible only within the class                |
| `protected`      | Accessible within the class and derived classes |

For basic encapsulation, `private` data with `public` member functions is a common pattern.

---

## 10. Encapsulation Example

Let's create a simple bank account.

```cpp
#include <iostream>
using namespace std;

class BankAccount {
private:
    double balance = 0;

public:
    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    double getBalance() {
        return balance;
    }
};

int main() {
    BankAccount account;

    account.deposit(5000);

    cout << "Balance: " << account.getBalance();

    return 0;
}
```


```output
Balance: 5000
```

The `balance` is hidden from direct access.

The `deposit()` function controls how money is added.

## 11. Controlling Data Changes

One advantage of encapsulation is that the class can control what values are allowed.

### Example

```cpp
#include <iostream>
using namespace std;

class Temperature {
private:
    double value = 0;

public:
    void setTemperature(double temperature) {
        if (temperature >= -273.15) {
            value = temperature;
        }
    }

    double getTemperature() {
        return value;
    }
};

int main() {
    Temperature temperature;

    temperature.setTemperature(25);

    cout << temperature.getTemperature();

    return 0;
}
```


```output
25
```

The setter prevents a value below absolute zero from being stored.

## 12. Encapsulation Improves Control

Suppose we have:

```cpp
class Student {
private:
    int marks;

public:
    void setMarks(int value) {
        if (value >= 0 && value <= 100) {
            marks = value;
        }
    }
};
```

The class decides how `marks` can be changed.

This gives the class more control over its internal state.

```text
Outside code
     ↓
setMarks()
     ↓
Validation
     ↓
marks
```

## 13. Encapsulation and Object State

The **state** of an object means the current values of its data members.

For example:

```text
Student
├── name = "Owais"
├── marks = 95
└── age = 18
```

Encapsulation helps protect this state.

Instead of allowing every part of the program to change the data directly, the class can provide specific functions for controlled changes.

## 14. Read-Only Data Through Encapsulation

Sometimes we may want outside code to read a value but not directly change it.

We can provide a getter without providing a setter.

### Example

```cpp
#include <iostream>
using namespace std;

class Student {
private:
    int rollNumber;

public:
    Student(int number) {
        rollNumber = number;
    }

    int getRollNumber() {
        return rollNumber;
    }
};

int main() {
    Student student(101);

    cout << student.getRollNumber();

    return 0;
}
```


```output
101
```

There is no public function for changing the roll number.

## 15. Encapsulation with Multiple Data Members

A class can encapsulate several related data members and functions.

### Example

```cpp
#include <iostream>
#include <string>
using namespace std;

class Student {
private:
    string name;
    int age;
    int marks;

public:
    Student(string studentName, int studentAge, int studentMarks) {
        name = studentName;
        age = studentAge;
        marks = studentMarks;
    }

    void display() {
        cout << "Name: " << name << endl;
        cout << "Age: " << age << endl;
        cout << "Marks: " << marks << endl;
    }
};

int main() {
    Student student("Owais", 18, 95);

    student.display();

    return 0;
}
```


```output
Name: Owais
Age: 18
Marks: 95
```

The student's data and related operation are grouped inside one class.

## 16. Encapsulation vs Data Hiding

These terms are related but not exactly identical.

### Encapsulation

Focuses on:

> **Grouping data and related functions together.**

### Data Hiding

Focuses on:

> **Restricting direct access to internal data.**

For example:

```cpp
class BankAccount {
private:
    double balance;

public:
    void deposit(double amount) {
        balance += amount;
    }
};
```

The class provides encapsulation, while `private` helps achieve data hiding.

---

## 17. Benefits of Encapsulation

Encapsulation can provide several benefits.

### 1. Data Protection

Internal data can be protected from direct access.

### 2. Validation

The class can check values before storing them.

### 3. Better Organization

Related data and functions stay together.

### 4. Easier Maintenance

Internal implementation can be changed without necessarily changing how outside code uses the class.

### 5. Controlled Access

The class decides which operations are available to outside code.

---

## 18. Example of Controlled Access

Consider a bank account.

Instead of allowing:

```cpp
account.balance = -5000;
```

we can provide:

```cpp
account.deposit(5000);
```

and:


```text
             BankAccount
                  │
        ┌─────────┴─────────┐
        │                   │

        │                   │
```

## 19. Encapsulation in Large Programs

Encapsulation becomes especially useful when programs contain many components.

For example, an online shopping system might have:

```text
Shopping System
│
├── Product
├── Customer
├── Cart
├── Order
└── Payment
```

Each class can keep its own data and related functions together.

## 20. Real-World Example 🌍

Consider a **bank account**.

A customer should not directly change the account balance.

Instead, the bank system provides operations such as:

* Deposit money
* Withdraw money
* Check balance

A simplified C++ version can be written as:

```cpp
#include <iostream>
using namespace std;

class BankAccount {
private:
    double balance = 0;

public:
    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    void withdraw(double amount) {
        if (amount > 0 && amount <= balance) {
            balance -= amount;
        }
    }

    double getBalance() {
        return balance;
    }
};

int main() {
    BankAccount account;

    account.deposit(5000);
    account.withdraw(1200);

    cout << "Balance: " << account.getBalance();

    return 0;
}
```


```output
Balance: 3800
```

The `balance` is private, so outside code cannot directly modify it.

The public functions control how the balance changes.

## Common Mistakes

### Mistake 1: Making all data members public

Example:

```cpp
class Student {
public:
    int marks;
};
```

This allows direct modification:

```cpp
student.marks = -100;
```

When data needs protection or validation, using `private` with suitable member functions is usually better.

---

### Mistake 2: Thinking `private` means the data can never be accessed

Private data can still be accessed by the class's member functions.

For example:

```cpp
class Student {
private:
    int marks;

public:
    void setMarks(int value) {
        marks = value;
    }
};
```

The member function can access `marks`.

---

### Mistake 3: Confusing getter and setter

A **setter** changes a value:

```cpp
setMarks(95);
```

A **getter** reads a value:

```cpp
getMarks();
```

---

### Mistake 4: Forgetting validation

If a setter accepts user-provided data, it may need validation.

For example:

```cpp
void setMarks(int value) {
    if (value >= 0 && value <= 100) {
        marks = value;
    }
}
```

---

### Mistake 5: Thinking encapsulation means only using `private`

`private` helps with data hiding, but encapsulation is broader.

Encapsulation is about **grouping related data and functions together and controlling access to the object's internal state**.

---

## Key Points 🔑

* Encapsulation is an important OOP concept.
* It groups related data and functions inside a class.
* `private` members help hide internal data.
* `public` member functions can provide controlled access.
* Getters are commonly used to read data.
* Setters are commonly used to change data.
* Setters can validate values before storing them.
* Encapsulation helps protect an object's internal state.
* It improves organization and can make programs easier to maintain.
* Encapsulation and data hiding are related but not exactly the same.
