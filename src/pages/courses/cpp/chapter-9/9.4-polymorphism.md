# Chapter 9: Object-Oriented Programming

## Section 4: Polymorphism

**Polymorphism** is one of the main concepts of Object-Oriented Programming.

The word **polymorphism** means **"many forms."**

In C++, polymorphism allows the same function name, operator, or interface to behave differently depending on the situation.

For example, a function named `sound()` can behave differently for different animals.

```text
Animal
  │
  ├── Dog → Bark
  ├── Cat → Meow
  └── Cow → Moo
```

The same idea, `sound()`, can have different behavior.

---

## 1. What is Polymorphism?

Polymorphism allows one interface to represent different behaviors.

For example:

```cpp
void sound();
```

The idea of `sound()` can be different for different objects.

A dog may produce:

```text
Bark
```

A cat may produce:

```text
Meow
```

So the same operation can have different behavior.

---

## 2. Types of Polymorphism

C++ mainly provides two broad forms of polymorphism:

### 1. Compile-Time Polymorphism

The behavior is determined during compilation.

Examples include:

* Function overloading
* Operator overloading

### 2. Run-Time Polymorphism

The behavior is determined while the program is running.

The most common mechanism is:

* Function overriding using virtual functions

```text
Polymorphism
     │
     ├── Compile-Time
     │      ├── Function Overloading
     │      └── Operator Overloading
     │
     └── Run-Time
            └── Virtual Functions
```

---

## 3. Compile-Time Polymorphism

In compile-time polymorphism, the compiler determines which function should be called.

Function overloading is a common example.

### Example

```cpp
#include <iostream>
using namespace std;

class Calculator {
public:
    int add(int a, int b) {
        return a + b;
    }

    double add(double a, double b) {
        return a + b;
    }
};

int main() {
    Calculator calc;

    cout << calc.add(10, 20) << endl;
    cout << calc.add(2.5, 3.5) << endl;

    return 0;
}
```


```output
30
6
```

The compiler selects the appropriate `add()` function based on the arguments.

---

## 4. Function Overloading and Polymorphism

Function overloading means having multiple functions with the same name but different parameter lists.

For example:

```cpp
class Print {
public:
    void show(int value) {
        cout << value << endl;
    }

    void show(double value) {
        cout << value << endl;
    }
};
```

The function name is the same:

```text
show()
```

But the parameter types are different.

This is called **compile-time polymorphism**.

---

## 5. Operator Overloading

C++ also allows certain operators to be given special behavior for user-defined types.

For example, the `+` operator normally adds numbers.

```cpp
int result = 10 + 20;
```

We can also define how `+` should work with objects.

### Example

```cpp
#include <iostream>
using namespace std;

class Number {
public:
    int value;

    Number(int v) {
        value = v;
    }

    Number operator+(Number other) {
        return Number(value + other.value);
    }
};

int main() {
    Number a(10);
    Number b(20);

    Number c = a + b;

    cout << c.value << endl;

    return 0;
}
```


```output
30
```

Here, the `+` operator is overloaded for the `Number` class.

This is another example of compile-time polymorphism.

---

## 6. Run-Time Polymorphism

Run-time polymorphism allows the program to decide which function implementation to execute while the program is running.

It is commonly achieved using:

* Inheritance
* Function overriding
* Virtual functions

Consider a base class `Animal` and derived classes `Dog` and `Cat`.

Each class can provide its own version of `sound()`.

```text
Animal
  │
  ├── Dog → sound()
  │
  └── Cat → sound()
```

---

## 7. Function Overriding

When a derived class provides its own implementation of a base-class function with the same function signature, it is called **function overriding**.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    void sound() {
        cout << "Animal sound" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() {
        cout << "Dog barks" << endl;
    }
};

int main() {
    Dog dog;

    dog.sound();

    return 0;
}
```


```output
Dog barks
```

Here, `Dog` provides its own `sound()` function.

However, this example by itself does **not** demonstrate dynamic dispatch through a base-class pointer. For run-time polymorphism, we normally use a virtual function.

---

## 8. Virtual Functions

A **virtual function** is a member function declared using the `virtual` keyword in the base class.

It allows the correct overridden function to be selected at run time when accessed through a base-class pointer or reference.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() {
        cout << "Animal sound" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

int main() {
    Animal* animal = new Dog();

    animal->sound();

    delete animal;

    return 0;
}
```


```output
Dog barks
```

Although `animal` is an `Animal*`, it points to a `Dog` object.

Because `sound()` is virtual, the `Dog` version is called.

---

## 9. Why Use the `virtual` Keyword?

Without `virtual`, a call through a base-class pointer is based on the pointer's static type.

With `virtual`, the overridden function can be selected according to the actual object.

### Without `virtual`

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    void sound() {
        cout << "Animal sound" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() {
        cout << "Dog barks" << endl;
    }
};

int main() {
    Animal* animal = new Dog();

    animal->sound();

    delete animal;

    return 0;
}
```


```output
Animal sound
```

The base-class function is called because `sound()` is not virtual.

---

### With `virtual`

```cpp
class Animal {
public:
    virtual void sound() {
        cout << "Animal sound" << endl;
    }
};
```

Now the derived implementation can be selected through the base pointer.

```output
Dog barks
```

---

## 10. The `override` Keyword

C++ provides the `override` keyword to clearly indicate that a derived-class function is intended to override a virtual function from the base class.

### Example

```cpp
class Animal {
public:
    virtual void sound() {
        cout << "Animal sound" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};
```

Using `override` helps the compiler detect mistakes.

For example, if the function signature does not correctly match an overridable base function, the compiler can report an error.

Using `override` is recommended when overriding virtual functions.

---

## 11. Polymorphism with Multiple Derived Classes

Multiple derived classes can provide different implementations of the same virtual function.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() {
        cout << "Animal sound" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

class Cat : public Animal {
public:
    void sound() override {
        cout << "Cat meows" << endl;
    }
};

int main() {
    Animal* animal1 = new Dog();
    Animal* animal2 = new Cat();

    animal1->sound();
    animal2->sound();

    delete animal1;
    delete animal2;

    return 0;
}
```


```output
Dog barks
Cat meows
```

The same function call:

```cpp
animal->sound();
```

can produce different results depending on the actual object.

This is **run-time polymorphism**.

---

## 12. Polymorphism Using References

Run-time polymorphism can also work through a base-class reference.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() {
        cout << "Animal sound" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

void makeSound(Animal& animal) {
    animal.sound();
}

int main() {
    Dog dog;

    makeSound(dog);

    return 0;
}
```


```output
Dog barks
```

The function accepts an `Animal&`, but the actual object is a `Dog`.

The virtual function mechanism selects `Dog::sound()`.

---

## 13. Pure Virtual Functions

A base class can declare a function as **pure virtual** when the base class should not provide a normal implementation for that function.

Syntax:

```cpp
virtual void sound() = 0;
```

A class containing a pure virtual function is called an **abstract class**.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() = 0;
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

int main() {
    Dog dog;

    dog.sound();

    return 0;
}
```


```output
Dog barks
```

The `Animal` class provides the interface for `sound()`.

The derived class provides the implementation.

---

## 14. Abstract Classes

A class containing at least one pure virtual function is an **abstract class**.

An abstract class cannot be instantiated directly.

For example:

```cpp
class Animal {
public:
    virtual void sound() = 0;
};
```

We cannot normally write:

```cpp
Animal animal;
```

because `Animal` is abstract.

But we can create objects of concrete derived classes:

```cpp
Dog dog;
```

This concept is useful when we want a common interface for different derived classes.

---

## 15. Polymorphism with Arrays of Pointers

Polymorphism becomes especially useful when we want to work with different derived objects using a common base type.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() {
        cout << "Animal sound" << endl;
    }

    virtual ~Animal() {
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

class Cat : public Animal {
public:
    void sound() override {
        cout << "Cat meows" << endl;
    }
};

int main() {
    Animal* animals[2];

    animals[0] = new Dog();
    animals[1] = new Cat();

    for (int i = 0; i < 2; i++) {
        animals[i]->sound();
    }

    delete animals[0];
    delete animals[1];

    return 0;
}
```


```output
Dog barks
Cat meows
```

The array stores pointers of the same base type:

```cpp
Animal*
```

but the pointers refer to different derived objects.

---

## 16. Virtual Destructors

When a class is intended to be used polymorphically, its destructor should generally be virtual.

For example:

```cpp
class Animal {
public:
    virtual ~Animal() {
    }
};
```

This ensures that deleting a derived object through a base-class pointer uses the appropriate destruction sequence.

Example:

```cpp
Animal* animal = new Dog();

delete animal;
```

A virtual destructor is important when objects are deleted through base-class pointers.

---

## 17. Compile-Time vs Run-Time Polymorphism

| Feature               | Compile-Time                               | Run-Time           |
| --------------------- | ------------------------------------------ | ------------------ |
| Decision              | During compilation                         | During execution   |
| Common examples       | Function overloading, operator overloading | Virtual functions  |
| Inheritance required? | Not necessarily                            | Usually involved   |
| Main mechanism        | Overloading                                | Overriding         |
| Flexibility           | Lower at run time                          | Higher at run time |

---

## 18. Overloading vs Overriding

These two terms are different.

### Function Overloading

Same function name with different parameter lists.

```cpp
void add(int a, int b);
void add(double a, double b);
```

This is commonly used for compile-time polymorphism.

### Function Overriding

A derived class provides a new implementation of a virtual base-class function with a matching signature.

```cpp
class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks";
    }
};
```

This is used for run-time polymorphism.

## 19. Real-World Example 🌍

Consider a payment system.

Different payment methods can have the same operation:

```text
Payment
   │
   ├── CardPayment
   ├── UpiPayment
   └── CashPayment
```

Each payment method can implement `pay()` differently.

### Example

```cpp
#include <iostream>
using namespace std;

class Payment {
public:
    virtual void pay() {
        cout << "Making payment" << endl;
    }

    virtual ~Payment() {
    }
};

class CardPayment : public Payment {
public:
    void pay() override {
        cout << "Payment using card" << endl;
    }
};

class UpiPayment : public Payment {
public:
    void pay() override {
        cout << "Payment using UPI" << endl;
    }
};

int main() {
    Payment* payment1 = new CardPayment();
    Payment* payment2 = new UpiPayment();

    payment1->pay();
    payment2->pay();

    delete payment1;
    delete payment2;

    return 0;
}
```


```output
Payment using card
Payment using UPI
```

The same `pay()` operation behaves differently for different payment objects.

This is a practical example of polymorphism.

## Common Mistakes

### Mistake 1: Confusing overloading and overriding

Overloading means different parameter lists.

Overriding means a derived class replaces the implementation of a virtual base-class function.

---

### Mistake 2: Forgetting `virtual`

For dynamic dispatch through a base pointer or reference, the base function should be virtual.

```cpp
virtual void sound();
```

---

### Mistake 3: Thinking `override` creates polymorphism

The `override` keyword does not itself create run-time polymorphism.

It tells the compiler that the derived function is intended to override a virtual base function.

---

### Mistake 4: Creating an object of an abstract class

A class with a pure virtual function is abstract.

You cannot directly create an object of that class.

---

### Mistake 5: Forgetting a virtual destructor

If a class is used polymorphically and objects may be deleted through base-class pointers, a virtual destructor is generally appropriate.

---

## Key Points 🔑

* Polymorphism means **many forms**.
* It allows the same interface or operation to have different behavior.
* C++ supports compile-time and run-time polymorphism.
* Function overloading is a common example of compile-time polymorphism.
* Operator overloading is another compile-time example.
* Run-time polymorphism commonly uses inheritance and virtual functions.
* A virtual function can be overridden in a derived class.
* The `override` keyword clearly marks an overriding function.
* Pure virtual functions use `= 0`.
* A class containing a pure virtual function is abstract.
* Abstract classes cannot be instantiated directly.
* Base-class pointers or references can be used to access derived objects polymorphically.
* A virtual destructor is important for safe destruction through a base-class pointer.
