# Chapter 9: Object-Oriented Programming

## Section 5: Abstraction

**Abstraction** is one of the main concepts of Object-Oriented Programming.

Abstraction means **showing only the important details and hiding unnecessary implementation details**.

For example, when we use an ATM, we choose options such as:

```text
Withdraw Money
Deposit Money
Check Balance
```

We do not need to know all the internal operations performed by the ATM.

The user interacts with a simple interface while the complicated implementation remains hidden.

---

## 1. What is Abstraction?

Abstraction focuses on **what an object does** rather than **how it does it**.

For example:

```text
Car
 │
 ├── start()
 ├── accelerate()
 └── brake()
```

A user can call `start()` without needing to know every internal step used to start the engine.

In C++, abstraction can be implemented using:

* Classes
* Access specifiers
* Abstract classes
* Pure virtual functions

---

## 2. Real-World Example

Consider a mobile phone.

We can use:

```text
Call
Send Message
Take Photo
Play Music
```

But the user does not need to understand all the internal hardware and software operations behind these features.

The interface shows the important operations while hiding unnecessary details.

This is abstraction.

---

## 3. Abstraction Using Classes

A class can provide a simple interface while keeping implementation details private.

### Example

```cpp
#include <iostream>
using namespace std;

class Calculator {
private:
    int a;
    int b;

public:
    void setNumbers(int x, int y) {
        a = x;
        b = y;
    }

    int add() {
        return a + b;
    }
};

int main() {
    Calculator calc;

    calc.setNumbers(10, 20);

    cout << "Sum: " << calc.add() << endl;

    return 0;
}
```


```output
Sum: 30
```

The user of the class only needs to know how to use:

```cpp
setNumbers()
add()
```

The data members are kept private.

---

## 4. Hiding Implementation Details

Consider this function:

```cpp
int add(int a, int b) {
    return a + b;
}
```

A user can simply call:

```cpp
add(10, 20);
```

The user does not need to think about the internal statement:

```cpp
return a + b;
```

The function provides a simple interface.

This is one of the basic ideas behind abstraction.

---

## 5. Access Specifiers and Abstraction

C++ provides access specifiers to control which parts of a class can be accessed from outside.

The main access specifiers are:

* `public`
* `private`
* `protected`

For abstraction, `private` is especially useful for hiding implementation details.

### Example

```cpp
class BankAccount {
private:
    double balance;

public:
    void deposit(double amount) {
        balance += amount;
    }
};
```

The `balance` variable is hidden from direct access.

The user interacts with the public `deposit()` function instead.

---

## 6. Public Interface

The **public interface** is the set of public functions or members through which other code interacts with an object.

For example:

```cpp
class Student {
private:
    int marks;

public:
    void setMarks(int value) {
        marks = value;
    }

    int getMarks() {
        return marks;
    }
};
```

The public interface contains:

```text
setMarks()
getMarks()
```

The internal variable:

```text
marks
```

is private.

The outside code does not directly access the internal data.

---

## 7. Abstraction Using Abstract Classes

C++ supports stronger forms of abstraction using **abstract classes**.

An abstract class is a class that cannot be instantiated directly.

It commonly contains at least one **pure virtual function**.

A pure virtual function is declared using:

```cpp
virtual void functionName() = 0;
```

---

## 8. Pure Virtual Functions

### Example

```cpp
#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() = 0;
};
```

Here:

```cpp
virtual void draw() = 0;
```

is a pure virtual function.

The `Shape` class becomes an abstract class.

We cannot directly create:

```cpp
Shape shape;
```

Instead, derived classes provide the implementation.

---

## 9. Implementing an Abstract Class

A derived class can implement the pure virtual function.

### Example

```cpp
#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() = 0;
};

class Circle : public Shape {
public:
    void draw() override {
        cout << "Drawing Circle" << endl;
    }
};

int main() {
    Circle circle;

    circle.draw();

    return 0;
}
```


```output
Drawing Circle
```

`Shape` defines what operation should exist:

```cpp
draw()
```

`Circle` defines how the operation works.

This is a common way of achieving abstraction in C++.

---

## 10. Abstraction Through Different Derived Classes

Different derived classes can implement the same abstract interface differently.

### Example

```cpp
#include <iostream>
using namespace std;

class Shape {
public:
    virtual void draw() = 0;
};

class Circle : public Shape {
public:
    void draw() override {
        cout << "Drawing Circle" << endl;
    }
};

class Rectangle : public Shape {
public:
    void draw() override {
        cout << "Drawing Rectangle" << endl;
    }
};

int main() {
    Circle circle;
    Rectangle rectangle;

    circle.draw();
    rectangle.draw();

    return 0;
}
```


```output
Drawing Circle
Drawing Rectangle
```

The abstract class provides a common interface:

```cpp
draw()
```

Each derived class provides its own implementation.

---

## 11. Abstraction and Polymorphism

Abstraction and polymorphism are closely related, but they are not the same concept.

### Abstraction

Focuses on:

```text
What should be done?
```

### Polymorphism

Focuses on:

```text
Which implementation should be used?
```

For example:

```cpp
class Shape {
public:
    virtual void draw() = 0;
};
```

The abstract class says that every derived shape should provide `draw()`.

Then:

```cpp
class Circle : public Shape {
public:
    void draw() override {
        cout << "Circle";
    }
};
```

and:

```cpp
class Rectangle : public Shape {
public:
    void draw() override {
        cout << "Rectangle";
    }
};
```

The common interface provides abstraction, while virtual dispatch can provide run-time polymorphism.

---

## 12. Abstraction vs Encapsulation

Abstraction and encapsulation are related but different.

### Abstraction

Hides unnecessary implementation details.

It focuses on:

```text
What an object does
```

### Encapsulation

Groups data and functions together and controls access to the object's internal state.

It focuses on:

```text
How access to the object's data is controlled
```

### Example

```cpp
class BankAccount {
private:
    double balance;

public:
    void deposit(double amount) {
        balance += amount;
    }

    double getBalance() {
        return balance;
    }
};
```

Here:

* Keeping `balance` private demonstrates encapsulation and access control.
* Providing simple operations such as `deposit()` and `getBalance()` supports abstraction.

## 13. Abstraction with a Real-World Payment System

Suppose a payment application supports different payment methods.

The application can define a common interface:

```text
Payment
   │
   ├── CardPayment
   ├── UpiPayment
   └── CashPayment
```

The application only needs to know that every payment method can perform `pay()`.

### Example

```cpp
#include <iostream>
using namespace std;

class Payment {
public:
    virtual void pay() = 0;

    virtual ~Payment() {
    }
};

class CardPayment : public Payment {
public:
    void pay() override {
        cout << "Payment using card" << endl;
    }
};

class UpiPayment : public Payment {
public:
    void pay() override {
        cout << "Payment using UPI" << endl;
    }
};

int main() {
    CardPayment card;
    UpiPayment upi;

    card.pay();
    upi.pay();

    return 0;
}
```


```output
Payment using card
Payment using UPI
```

The `Payment` class defines the common operation.

Each payment class decides how that operation is performed.

---

## 14. Abstract Class Cannot Be Instantiated

Consider:

```cpp
class Animal {
public:
    virtual void sound() = 0;
};
```

Because `Animal` contains a pure virtual function, it is abstract.

This is not allowed:

```cpp
Animal animal;
```

But this is allowed:

```cpp
class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks";
    }
};

Dog dog;
```

The derived class provides an implementation for the pure virtual function.

---

## 15. Abstract Class Can Have Normal Functions

An abstract class does not have to contain only pure virtual functions.

It can also contain normal member functions.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() = 0;

    void eat() {
        cout << "Animal is eating" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

int main() {
    Dog dog;

    dog.eat();
    dog.sound();

    return 0;
}
```


```output
Animal is eating
Dog barks
```

The abstract class can provide common functionality as well as abstract operations.

## 16. Advantages of Abstraction

### 1. Reduces Complexity

Users do not need to understand every internal detail.

### 2. Provides a Simple Interface

Only important operations are exposed.

### 3. Improves Code Organization

Classes can separate interface from implementation.

### 4. Makes Programs Easier to Use

Users can work with simple functions instead of complicated internal logic.

### 5. Supports Flexible Design

Abstract classes can define common interfaces for different derived classes.

---

## 17. Abstraction and Interface Design

A good abstraction exposes only what is necessary.

For example, instead of exposing every internal detail of a bank account, we can provide operations such as:

```text
deposit()
withdraw()
getBalance()
```

The user interacts with these operations.

The internal representation of the account remains hidden.

This makes the class easier to use and maintain.

## 18. Real-World Example 🌍

Consider a vehicle system.

A vehicle can provide common operations:

```text
start()
stop()
```

Different vehicles may implement these operations differently.

```text
             Vehicle
                │
        ┌───────┴───────┐
        ↓               ↓
       Car             Bike
```

### Example

```cpp
#include <iostream>
using namespace std;

class Vehicle {
public:
    virtual void start() = 0;

    virtual ~Vehicle() {
    }
};

class Car : public Vehicle {
public:
    void start() override {
        cout << "Car starts with a key or button" << endl;
    }
};

class Bike : public Vehicle {
public:
    void start() override {
        cout << "Bike starts with a key or button" << endl;
    }
};

int main() {
    Car car;
    Bike bike;

    car.start();
    bike.start();

    return 0;
}
```


```output
Car starts with a key or button
Bike starts with a key or button
```

The `Vehicle` class defines the common operation.

The derived classes provide the actual implementation.

## Common Mistakes

### Mistake 1: Confusing abstraction with encapsulation

They are related, but they are not identical.

* Abstraction hides unnecessary implementation details.
* Encapsulation groups data and functions and controls access.

---

### Mistake 2: Trying to create an object of an abstract class

This is not allowed:

```cpp
Shape shape;
```

if `Shape` contains a pure virtual function.

---

### Mistake 3: Forgetting `= 0`

A pure virtual function is declared like:

```cpp
virtual void draw() = 0;
```

The `= 0` is important.

---

### Mistake 4: Not implementing a pure virtual function

If a derived class does not implement all required pure virtual functions, it can remain abstract.

Such a class cannot be instantiated directly.

---

### Mistake 5: Thinking abstraction means hiding all data

Abstraction is not simply about making every variable private.

It is about exposing the important interface while hiding unnecessary implementation details.

---

## Key Points 🔑

* Abstraction means showing important details and hiding unnecessary implementation details.
* It focuses on **what an object does** rather than **how it does it**.
* Classes and access specifiers can help implement abstraction.
* Abstract classes provide a common interface for derived classes.
* A pure virtual function is declared using `= 0`.
* A class with at least one pure virtual function is abstract.
* Abstract classes cannot be instantiated directly.
* Derived classes can implement pure virtual functions.
* Abstract classes can also contain normal member functions.
* Abstraction and encapsulation are related but different concepts.
* Abstraction can work together with run-time polymorphism.
* Good abstraction makes programs easier to use, understand, and maintain.
