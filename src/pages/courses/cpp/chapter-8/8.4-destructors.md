# Chapter 8: Classes & Objects

## Section 4: Destructors

A **destructor** is a special member function that is automatically called when an object is destroyed.

Destructors are mainly used to perform **cleanup work** before an object is removed from memory.

A destructor has the **same name as the class**, but its name starts with a tilde (`~`).

---

## 1. What is a Destructor?

A destructor is a special function that runs automatically when an object is destroyed.

### Example

```cpp
#include <iostream>
using namespace std;

class Student {
public:
    ~Student() {
        cout << "Destructor called!" << endl;
    }
};

int main() {
    Student student;

    return 0;
}
```


```output
Destructor called!
```

When the `student` object reaches the end of its lifetime, its destructor is automatically called.

---

## 2. Destructor Syntax

The basic syntax is:

```cpp
class ClassName {
public:
    ~ClassName() {
        // cleanup code
    }
};
```

Important rules:

* The destructor name must be the same as the class name.
* It must begin with `~`.
* A destructor does not have a return type.
* A destructor does not take parameters.
* A class can have only one destructor.
* A destructor is called automatically when an object is destroyed.

---

## 3. Constructor vs Destructor

A constructor and destructor have opposite purposes.

| Constructor                                       | Destructor                         |
| ------------------------------------------------- | ---------------------------------- |
| Initializes an object                             | Performs cleanup                   |
| Called when an object is created                  | Called when an object is destroyed |
| Has the same name as the class                    | Same name with `~` before it       |
| Can have parameters                               | Cannot have parameters             |
| A class can have multiple overloaded constructors | A class has only one destructor    |

Example:

```cpp
class Student {
public:
    Student() {
        cout << "Constructor" << endl;
    }

    ~Student() {
        cout << "Destructor" << endl;
    }
};
```

The constructor prepares the object, while the destructor performs cleanup when the object is destroyed.

---

## 4. When is a Destructor Called?

For a local object, the destructor is normally called automatically when the object goes out of scope.

### Example

```cpp
#include <iostream>
using namespace std;

class Test {
public:
    Test() {
        cout << "Constructor called" << endl;
    }

    ~Test() {
        cout << "Destructor called" << endl;
    }
};

int main() {
    Test obj;

    cout << "Inside main" << endl;

    return 0;
}
```


```output
Constructor called
Inside main
Destructor called
```

The destructor runs after the object has reached the end of its lifetime.

---

## 5. Destructor Is Called Automatically

We normally do not call a destructor like a normal member function.

For example:

```cpp
Test obj;
```

creates an object.

When `obj` is destroyed, C++ automatically calls:

```cpp
~Test()
```

This automatic behavior makes destructors useful for cleanup.

---

## 6. Destructor Name

Suppose the class name is:

```cpp
class Car {
};
```

The destructor must be:

```cpp
~Car()
```

### Example

```cpp
#include <iostream>
using namespace std;

class Car {
public:
    ~Car() {
        cout << "Car destroyed" << endl;
    }
};

int main() {
    Car car;

    return 0;
}
```


```output
Car destroyed
```

The `~` symbol is an important part of the destructor name.

---

## 7. Destructor Has No Return Type

A destructor does not have a return type.

Correct:

```cpp
class Student {
public:
    ~Student() {
    }
};
```

Incorrect:

```cpp
class Student {
public:
    void ~Student() {
    }
};
```

A destructor must not have `void`, `int`, `double`, or any other return type.

---

## 8. Destructor Cannot Have Parameters

A destructor cannot take parameters.

Correct:

```cpp
class Student {
public:
    ~Student() {
    }
};
```

Incorrect:

```cpp
class Student {
public:
    ~Student(int value) {
    }
};
```

A destructor always has an empty parameter list.

---

## 9. A Class Has Only One Destructor

Unlike constructors, destructors cannot be overloaded.

A class can have:

```cpp
Student();
Student(string name);
Student(int age);
```

but it cannot have multiple destructors such as:

```cpp
~Student();
~Student(int value);
```

There can be only one destructor for a class.

---

## 10. Destructor with Multiple Objects

When multiple objects are created, each object has its own destructor call.

### Example

```cpp
#include <iostream>
using namespace std;

class Student {
public:
    Student() {
        cout << "Created" << endl;
    }

    ~Student() {
        cout << "Destroyed" << endl;
    }
};

int main() {
    Student student1;
    Student student2;

    return 0;
}
```


```output
Created
Created
Destroyed
Destroyed
```

Both objects are destroyed when they reach the end of their lifetime.

For local objects in the same scope, destruction happens in the **reverse order of creation**.

So `student2` is destroyed before `student1`.

---

## 11. Destruction in Reverse Order

Consider:

```cpp
#include <iostream>
using namespace std;

class Number {
public:
    int value;

    Number(int n) {
        value = n;
        cout << "Created " << value << endl;
    }

    ~Number() {
        cout << "Destroyed " << value << endl;
    }
};

int main() {
    Number n1(1);
    Number n2(2);
    Number n3(3);

    return 0;
}
```


```output
Created 1
Created 2
Created 3
Destroyed 3
Destroyed 2
Destroyed 1
```

The objects are destroyed in reverse order:

```text
n1 → n2 → n3
       ↓
n3 → n2 → n1
```

---

## 12. Destructor and Scope

A destructor is called when an object's lifetime ends.

For a local object, this commonly happens when the object goes out of scope.

### Example

```cpp
#include <iostream>
using namespace std;

class Test {
public:
    Test() {
        cout << "Created" << endl;
    }

    ~Test() {
        cout << "Destroyed" << endl;
    }
};

int main() {

    {
        Test obj;
        cout << "Inside block" << endl;
    }

    cout << "Outside block" << endl;

    return 0;
}
```


```output
Created
Inside block
Destroyed
Outside block
```

The object `obj` exists only inside the inner block.

When the block ends, `obj` is destroyed and its destructor runs.

---

## 13. Destructor and Dynamic Memory

Destructors are especially useful when a class manages resources.

For example, a class may dynamically allocate memory.

### Example

```cpp
#include <iostream>
using namespace std;

class Numbers {
private:
    int* data;

public:
    Numbers() {
        data = new int[3];

        data[0] = 10;
        data[1] = 20;
        data[2] = 30;
    }

    ~Numbers() {
        delete[] data;
        cout << "Memory cleaned up" << endl;
    }

    void display() {
        cout << data[0] << " ";
        cout << data[1] << " ";
        cout << data[2] << endl;
    }
};

int main() {
    Numbers numbers;

    numbers.display();

    return 0;
}
```


```output
10 20 30
Memory cleaned up
```

Here:

* The constructor allocates dynamic memory.
* The object uses that memory.
* The destructor releases the memory using `delete[]`.

This helps prevent a **memory leak**.

---

## 14. Destructor for Cleanup

A destructor can be used to release resources owned by an object.

Examples of resources can include:

* Dynamically allocated memory
* Files opened by an object
* Other resources managed by a class

The general idea is:

```text
Object created
      ↓
Resource acquired
      ↓
Object used
      ↓
Object destroyed
      ↓
Resource cleaned up
```

---

## 15. Constructor and Destructor Together

Constructors and destructors often work as a pair.

### Example

```cpp
#include <iostream>
using namespace std;

class FileManager {
public:
    FileManager() {
        cout << "Resource acquired" << endl;
    }

    ~FileManager() {
        cout << "Resource released" << endl;
    }
};

int main() {
    FileManager file;

    cout << "Using resource" << endl;

    return 0;
}
```


```output
Resource acquired
Using resource
Resource released
```

The constructor performs setup, and the destructor performs cleanup.

---

## 16. Destructor with Private Members

A destructor can access private data members because it is a member function of the class.

### Example

```cpp
#include <iostream>
using namespace std;

class Student {
private:
    int marks;

public:
    Student(int m) {
        marks = m;
    }

    ~Student() {
        cout << "Student object with marks "
             << marks << " destroyed" << endl;
    }
};

int main() {
    Student student(95);

    return 0;
}
```


```output
Student object with marks 95 destroyed
```

The destructor can directly access `marks`.

---

## 17. Destructor and Dynamically Created Objects

Objects can also be created dynamically using `new`.

For a dynamically created object, the destructor is called when the object is destroyed using `delete`.

### Example

```cpp
#include <iostream>
using namespace std;

class Test {
public:
    Test() {
        cout << "Created" << endl;
    }

    ~Test() {
        cout << "Destroyed" << endl;
    }
};

int main() {
    Test* obj = new Test();

    delete obj;

    return 0;
}
```


```output
Created
Destroyed
```

Here:

```cpp
delete obj;
```

destroys the dynamically allocated object and causes its destructor to run.

---

## 18. Destructor and Dynamic Arrays of Objects

When an array of objects is dynamically created, `delete[]` is used to destroy the array.

### Example

```cpp
#include <iostream>
using namespace std;

class Test {
public:
    Test() {
        cout << "Created" << endl;
    }

    ~Test() {
        cout << "Destroyed" << endl;
    }
};

int main() {
    Test* objects = new Test[3];

    delete[] objects;

    return 0;
}
```


```output
Created
Created
Created
Destroyed
Destroyed
Destroyed
```

Each object gets its destructor call.

---

## 19. Destructor Should Not Be Called Manually

For normal object management, let C++ call the destructor automatically.

For example:

```cpp
Test obj;
```

When `obj` reaches the end of its lifetime, C++ calls its destructor.

For a dynamically allocated object:

```cpp
Test* obj = new Test();
delete obj;
```

The `delete` expression causes the object's destructor to run.

Manually invoking a destructor is an advanced technique and is generally not needed for beginner programs.

---

## 20. Real-World Example 🌍

Imagine a simple system that manages a temporary resource.

When the object is created, the resource is prepared.

When the object is destroyed, the resource is cleaned up.

```cpp
#include <iostream>
using namespace std;

class Printer {
public:
    Printer() {
        cout << "Printer resource ready" << endl;
    }

    void printDocument() {
        cout << "Printing document" << endl;
    }

    ~Printer() {
        cout << "Printer resource released" << endl;
    }
};

int main() {
    Printer printer;

    printer.printDocument();

    return 0;
}
```


```output
Printer resource ready
Printing document
Printer resource released
```

The constructor prepares the object, while the destructor performs the final cleanup.

## Common Mistakes

### Mistake 1: Forgetting the `~`

Incorrect:

```cpp
Student() {
}
```

This is a constructor, not a destructor.

Correct:

```cpp
~Student() {
}
```

---

### Mistake 2: Giving the destructor a return type

Incorrect:

```cpp
void ~Student() {
}
```

Correct:

```cpp
~Student() {
}
```

---

### Mistake 3: Adding parameters to a destructor

Incorrect:

```cpp
~Student(int value) {
}
```

Correct:

```cpp
~Student() {
}
```

---

### Mistake 4: Creating multiple destructors

A class cannot have multiple destructors.

Incorrect:

```cpp
~Student() {
}

~Student(int value) {
}
```

A class can have only one destructor.

---

### Mistake 5: Using `delete` instead of `delete[]`

If memory was allocated using:

```cpp
int* numbers = new int[5];
```

it should be released using:

```cpp
delete[] numbers;
```

For a single object created using `new`:

```cpp
Student* student = new Student();
```

use:

```cpp
delete student;
```

---

## Key Points 🔑

* A destructor is a special member function used for cleanup.
* Its name is the class name preceded by `~`.
* A destructor has no return type.
* A destructor cannot take parameters.
* A class can have only one destructor.
* Destructors are called automatically when objects are destroyed.
* Local objects are commonly destroyed when they go out of scope.
* Local objects in the same scope are destroyed in reverse order of creation.
* `delete` destroys a single dynamically allocated object.
* `delete[]` destroys a dynamically allocated array.
* Destructors are useful for releasing resources such as dynamic memory.
* Constructors and destructors often work together: constructor for setup and destructor for cleanup.
