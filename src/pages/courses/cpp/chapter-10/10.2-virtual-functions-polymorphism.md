# Chapter 10: Advanced OOP & C++ Features

## Section 2: Virtual Functions & Runtime Polymorphism

**Virtual functions** are an important feature of C++ used to achieve **runtime polymorphism**.

Runtime polymorphism allows a program to decide which overridden function should be called **at runtime**, based on the actual object.

It is commonly used with:

* Inheritance
* Base-class pointers or references
* Virtual functions
* Function overriding

---

## 1. What is a Virtual Function?

A **virtual function** is a member function declared using the `virtual` keyword in a base class.

### Basic Syntax

```cpp
class Base {
public:
    virtual void display() {
        // code
    }
};
```

A derived class can override this function.

```cpp
class Derived : public Base {
public:
    void display() override {
        // different implementation
    }
};
```

---

## 2. What is Runtime Polymorphism?

Runtime polymorphism means that the function to execute is determined while the program is running.

Consider:

```text
          Animal
         /      \
       Dog      Cat
        |        |
      sound()  sound()
```

Both `Dog` and `Cat` have their own version of `sound()`.

A base-class pointer can refer to either object.

The correct function can then be selected at runtime.

---

## 3. Simple Virtual Function Example

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() {
        cout << "Animal makes a sound" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

int main() {
    Animal* animal = new Dog();

    animal->sound();

    delete animal;

    return 0;
}
```


```output
Dog barks
```

Although `animal` is an `Animal*`, it points to a `Dog` object.

Because `sound()` is virtual, the `Dog` version is called.

---

## 4. Without a Virtual Function

To understand the importance of `virtual`, first consider what happens without it.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    void sound() {
        cout << "Animal makes a sound" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() {
        cout << "Dog barks" << endl;
    }
};

int main() {
    Animal* animal = new Dog();

    animal->sound();

    delete animal;

    return 0;
}
```


```output
Animal makes a sound
```

The base-class version is called because `sound()` is not virtual.

---

## 5. Adding `virtual`

Now add `virtual` to the base-class function.

```cpp
class Animal {
public:
    virtual void sound() {
        cout << "Animal makes a sound" << endl;
    }
};
```

The derived class overrides it:

```cpp
class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};
```

Now:

```cpp
Animal* animal = new Dog();

animal->sound();
```

produces:

```output
Dog barks
```

The actual object is a `Dog`, so the overridden `Dog::sound()` function is selected.

---

## 6. Base-Class Pointer and Derived Object

A base-class pointer can point to an object of a derived class.

For example:

```cpp
Dog dog;

Animal* animal = &dog;
```

Here:

* `animal` is an `Animal*`.
* `dog` is a `Dog` object.
* `animal` points to the `Dog` object.

If the function is virtual, calling it through `animal` can select the derived implementation.

---

## 7. Multiple Derived Classes

Runtime polymorphism becomes more useful when multiple classes derive from the same base class.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() {
        cout << "Animal sound" << endl;
    }

    virtual ~Animal() {
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

class Cat : public Animal {
public:
    void sound() override {
        cout << "Cat meows" << endl;
    }
};

int main() {
    Animal* animal1 = new Dog();
    Animal* animal2 = new Cat();

    animal1->sound();
    animal2->sound();

    delete animal1;
    delete animal2;

    return 0;
}
```


```output
Dog barks
Cat meows
```

The same function call:

```cpp
animal->sound();
```

can produce different results depending on the actual object.

---

## 8. Function Overriding

Runtime polymorphism uses **function overriding**.

A derived class provides its own implementation of a virtual function from the base class.

### Example

```cpp
class Animal {
public:
    virtual void sound() {
        cout << "Animal sound";
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks";
    }
};
```

Both functions have the same name and compatible function signature.

The derived version overrides the base version.

---

## 9. The `override` Keyword

C++ provides the `override` keyword to indicate that a derived-class function is intended to override a virtual function.

### Example

```cpp
class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks";
    }
};
```

Using `override` helps the compiler detect mistakes.

For example, if the function does not correctly override a virtual base function, the compiler can report an error.

It is good practice to use `override` when overriding virtual functions.

---

## 10. Virtual Functions Through References

Runtime polymorphism can also work through a base-class reference.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() {
        cout << "Animal sound" << endl;
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

void makeSound(Animal& animal) {
    animal.sound();
}

int main() {
    Dog dog;

    makeSound(dog);

    return 0;
}
```


```output
Dog barks
```

The function receives an `Animal&`, but the actual object is a `Dog`.

Because `sound()` is virtual, the derived implementation is called.

---

## 11. Runtime Polymorphism with Arrays of Pointers

We can store pointers to different derived objects in an array of base-class pointers.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() {
        cout << "Animal sound" << endl;
    }

    virtual ~Animal() {
    }
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

class Cat : public Animal {
public:
    void sound() override {
        cout << "Cat meows" << endl;
    }
};

int main() {
    Animal* animals[2];

    animals[0] = new Dog();
    animals[1] = new Cat();

    for (int i = 0; i < 2; i++) {
        animals[i]->sound();
    }

    delete animals[0];
    delete animals[1];

    return 0;
}
```


```output
Dog barks
Cat meows
```

The array has one common pointer type:

```cpp
Animal*
```

but the objects can be different derived types.

---

## 12. Pure Virtual Functions

A virtual function can be made **pure virtual**.

Syntax:

```cpp
virtual void sound() = 0;
```

A class containing a pure virtual function becomes an **abstract class**.

### Example

```cpp
#include <iostream>
using namespace std;

class Animal {
public:
    virtual void sound() = 0;
};

class Dog : public Animal {
public:
    void sound() override {
        cout << "Dog barks" << endl;
    }
};

int main() {
    Dog dog;

    dog.sound();

    return 0;
}
```


```output
Dog barks
```

The `Animal` class defines what derived classes must provide.

---

## 13. Abstract Base Class

An abstract class cannot be instantiated directly.

For example:

```cpp
class Animal {
public:
    virtual void sound() = 0;
};
```

This is not allowed:

```cpp
Animal animal;
```

because `Animal` is abstract.

But a derived class can be instantiated if it implements the pure virtual function:

```cpp
Dog dog;
```

---

## 14. Virtual Destructor

When a class is used polymorphically, its destructor should generally be virtual if objects may be deleted through base-class pointers.

### Example

```cpp
class Animal {
public:
    virtual ~Animal() {
    }
};
```

Then:

```cpp
Animal* animal = new Dog();

delete animal;
```

allows the derived object to be destroyed through the base-class interface correctly.

---

## 15. Why Use a Virtual Destructor?

Consider a base pointer:

```cpp
Animal* animal = new Dog();
```

The pointer type is `Animal*`, but the actual object is `Dog`.

If the object is deleted through the base pointer, a virtual destructor ensures the appropriate destructor chain is used.

A common polymorphic base class therefore uses:

```cpp
virtual ~Animal() = default;
```

or an equivalent virtual destructor definition.

---

## 16. Runtime Polymorphism and Memory

A common way to demonstrate runtime polymorphism is:

```cpp
Animal* animal = new Dog();

animal->sound();

delete animal;
```

Here:

1. `new Dog()` creates a `Dog` object.
2. The address is stored in an `Animal*`.
3. `animal->sound()` calls the virtual function.
4. `delete animal` destroys the object.

For modern C++, smart pointers are often preferred for automatic memory management, but raw pointers are useful for learning the basic mechanism.

## 17. Runtime Polymorphism Using Stack Objects

Runtime polymorphism does not require `new`.

### Example

```cpp
#include <iostream>

        cout << "Animal sound" << endl;
    }
};

public:

        cout << "Dog barks" << endl;
    }

    animal.sound();
}

int main() {
    Dog dog;

    makeSound(dog);

    return 0;
}
```


```output
Dog barks
```

The base reference refers to the `Dog` object.

## 18. Static Binding vs Dynamic Binding

The difference can be understood as follows.

### Static Binding

The function call is determined during compilation.

This is commonly associated with non-virtual functions.

### Dynamic Binding

The function call is determined at runtime based on the actual object.

This is enabled by virtual functions when accessed through a base pointer or reference.

```text
Static Binding
     ↓
Compile time

Dynamic Binding
     ↓
Runtime
```

---

## 19. Compile-Time vs Runtime Polymorphism

| Feature              | Compile-Time Polymorphism | Runtime Polymorphism   |
| -------------------- | ------------------------- | ---------------------- |
| Decision             | Compile time              | Runtime                |
| Common example       | Function overloading      | Virtual functions      |
| Main concept         | Overloading               | Overriding             |
| Inheritance required | Not necessarily           | Commonly used          |
| Flexibility          | Determined earlier        | Determined dynamically |

## 20. Real-World Example 🌍

Consider a payment application.

Different payment methods can implement the same `pay()` operation differently.

```text
              Payment
             /       \
            /         \
      CardPayment    UpiPayment
```

### Example

```cpp
#include <iostream>
using namespace std;

class Payment {
public:
    virtual void pay() = 0;

    virtual ~Payment() {
    }
};

class CardPayment : public Payment {
public:
    void pay() override {
        cout << "Payment using card" << endl;
    }
};

class UpiPayment : public Payment {
public:
    void pay() override {
        cout << "Payment using UPI" << endl;
    }
};

void processPayment(Payment& payment) {
    payment.pay();
}

int main() {
    CardPayment card;
    UpiPayment upi;

    processPayment(card);
    processPayment(upi);

    return 0;
}
```


```output
Payment using card
Payment using UPI
```

The `processPayment()` function works with the common `Payment` interface.

The actual implementation is selected according to the object passed to it.

This is a practical use of runtime polymorphism.

---

## 21. Advantages of Runtime Polymorphism

### 1. Flexibility

The same interface can work with different object types.

### 2. Code Reusability

A common function can work with many derived classes.

### 3. Easy Extension

New derived classes can be added without changing code that uses the common interface.

### 4. Better Design

Programs can be designed around common interfaces instead of specific implementations.

### 5. Supports Abstraction

Abstract base classes can define common operations while derived classes provide the implementation.

---

## Common Mistakes

### Mistake 1: Forgetting `virtual`

Without `virtual`, a base-pointer call to a non-virtual function does not provide dynamic dispatch.

---

### Mistake 2: Confusing overriding with overloading

**Overriding** involves a derived class providing a new implementation of a virtual base-class function.

**Overloading** uses the same function name with different parameter lists.

---

### Mistake 3: Thinking `override` is required for overriding

The `override` keyword is recommended because it helps the compiler check the programmer's intention, but the keyword itself is not what makes a virtual function virtual.

---

### Mistake 4: Creating an object of an abstract class

A class with a pure virtual function is abstract and cannot be instantiated directly.

---

### Mistake 5: Forgetting a virtual destructor

If a polymorphic object may be deleted through a base-class pointer, the base class should generally have a virtual destructor.

---

## Key Points 🔑

* A virtual function is declared using the `virtual` keyword.
* Virtual functions are commonly used to achieve runtime polymorphism.
* Runtime polymorphism selects an overridden function according to the actual object.
* Base-class pointers and references can refer to derived objects.
* `override` helps the compiler check that a function correctly overrides a virtual function.
* Pure virtual functions use `= 0`.
* A class containing a pure virtual function is abstract.
* Abstract classes cannot be instantiated directly.
* Virtual destructors are important for polymorphic base classes.
* Runtime polymorphism provides flexibility and supports extensible designs.
* Function overloading is compile-time polymorphism, while virtual-function overriding is runtime polymorphism.
