# Chapter 10: Advanced OOP & C++ Features

## Section 3: Multiple Inheritance

Multiple inheritance is an important feature of C++ where a single derived class can inherit from **more than one base class**.

For example, a `SmartPhone` class can inherit features from both a `Camera` class and a `Phone` class.

---

## 1. What is Multiple Inheritance?

In **single inheritance**, one derived class inherits from one base class.

In **multiple inheritance**, one derived class inherits from two or more base classes.

### Basic Syntax

```cpp
class Derived : public Base1, public Base2 {
    // members
};
```

Here:

* `Derived` is the child class.
* `Base1` is the first parent class.
* `Base2` is the second parent class.
* The derived class gets accessible members from both base classes.

---

## 2. Simple Example

Let's create two base classes: `Father` and `Mother`.

```cpp
#include <iostream>
using namespace std;

class Father {
public:
    void fatherFeature() {
        cout << "Feature from Father" << endl;
    }
};

class Mother {
public:
    void motherFeature() {
        cout << "Feature from Mother" << endl;
    }
};

class Child : public Father, public Mother {
};

int main() {
    Child obj;

    obj.fatherFeature();
    obj.motherFeature();

    return 0;
}
```


```output
Feature from Father
Feature from Mother
```

The `Child` class inherits from both `Father` and `Mother`.

Therefore, the object of `Child` can access members from both base classes.

---

## 3. How Multiple Inheritance Works

Consider this structure:

```text
        Father        Mother
           \            /
            \          /
               Child
```

The `Child` class inherits from both `Father` and `Mother`.

For example:

```cpp
class Child : public Father, public Mother {
};
```

The order of the base classes is:

```text
Father → Mother
```

The base classes are normally constructed in the order in which they appear in the inheritance list.

---

## 4. Calling Members from Multiple Base Classes

A derived class can directly use accessible members from both base classes.

```cpp
#include <iostream>
using namespace std;

class Printer {
public:
    void printDocument() {
        cout << "Printing document" << endl;
    }
};

class Scanner {
public:
    void scanDocument() {
        cout << "Scanning document" << endl;
    }
};

class AllInOne : public Printer, public Scanner {
};

int main() {
    AllInOne machine;

    machine.printDocument();
    machine.scanDocument();

    return 0;
}
```


```output
Printing document
Scanning document
```

Here, `AllInOne` gets functionality from both `Printer` and `Scanner`.

---

## 5. Multiple Inheritance with Data Members

A derived class can also use accessible data members from multiple base classes.

```cpp
#include <iostream>
using namespace std;

class Student {
public:
    string name = "Owais";
};

class Marks {
public:
    int score = 95;
};

class Result : public Student, public Marks {
};

int main() {
    Result r;

    cout << "Name: " << r.name << endl;
    cout << "Score: " << r.score << endl;

    return 0;
}
```


```output
Name: Owais
Score: 95
```

The `Result` object can access members inherited from both `Student` and `Marks`.

---

## 6. Calling Base Class Constructors

When a class inherits from multiple base classes, the constructors of the base classes are called before the derived class constructor.

```cpp
#include <iostream>
using namespace std;

class A {
public:
    A() {
        cout << "Constructor A" << endl;
    }
};

class B {
public:
    B() {
        cout << "Constructor B" << endl;
    }
};

class C : public A, public B {
public:
    C() {
        cout << "Constructor C" << endl;
    }
};

int main() {
    C obj;

    return 0;
}
```


```output
Constructor A
Constructor B
Constructor C
```

The order is:

1. Base class `A`
2. Base class `B`
3. Derived class `C`

The order of construction follows the order of the base classes in the class declaration.

---

## 7. Order of Destructors

Destructors are called in the **reverse order** of construction.

```cpp
#include <iostream>
using namespace std;

class A {
public:
    ~A() {
        cout << "Destructor A" << endl;
    }
};

class B {
public:
    ~B() {
        cout << "Destructor B" << endl;
    }
};

class C : public A, public B {
public:
    ~C() {
        cout << "Destructor C" << endl;
    }
};

int main() {
    C obj;

    return 0;
}
```


```output
Destructor C
Destructor B
Destructor A
```

The derived class destructor runs first, followed by base class destructors in reverse order.

## 8. Function Name Conflict

Multiple inheritance can cause a problem when two base classes have functions with the **same name**.

For example:

```cpp
#include <iostream>
using namespace std;

class A {
public:
    void show() {
        cout << "A show()" << endl;
    }
};

class B {
public:
    void show() {
        cout << "B show()" << endl;
    }
};

class C : public A, public B {
};

int main() {
    C obj;

    // obj.show();   // Ambiguous

    return 0;
}
```

The compiler cannot determine whether `show()` from `A` or `show()` from `B` should be called.

This is called **ambiguity**.

---

## 9. Resolving Ambiguity Using Scope Resolution

We can tell the compiler exactly which base class function we want.

```cpp
#include <iostream>
using namespace std;

class A {
public:
    void show() {
        cout << "A show()" << endl;
    }
};

class B {
public:
    void show() {
        cout << "B show()" << endl;
    }
};

class C : public A, public B {
};

int main() {
    C obj;

    obj.A::show();
    obj.B::show();

    return 0;
}
```


```output
A show()
B show()
```

The syntax is:

```cpp
object.BaseClass::function();
```

This removes the ambiguity.

---

## 10. Resolving the Conflict Inside the Derived Class

We can also create a function in the derived class that decides which base function should be used.

```cpp
#include <iostream>
using namespace std;

class A {
public:
    void show() {
        cout << "A show()" << endl;
    }
};

class B {
public:
    void show() {
        cout << "B show()" << endl;
    }
};

class C : public A, public B {
public:
    void show() {
        A::show();
    }
};

int main() {
    C obj;

    obj.show();

    return 0;
}
```


```output
A show()
```

Now `C::show()` provides a single clear way to call the required function.

---

## 11. Multiple Inheritance and Access Specifiers

Multiple inheritance can use different access modes.

For example:

```cpp
class C : public A, protected B {
};
```

Here:

* Members inherited from `A` using `public` inheritance keep their accessible public/protected access.
* Members inherited from `B` using `protected` inheritance are treated as protected in `C`.

The inheritance mode affects how inherited members can be accessed through the derived class.

---

## 12. Multiple Inheritance Example: Smart Device

Multiple inheritance can represent a class that combines different capabilities.

```cpp
#include <iostream>
using namespace std;

class Camera {
public:
    void takePhoto() {
        cout << "Taking photo" << endl;
    }
};

class MusicPlayer {
public:
    void playMusic() {
        cout << "Playing music" << endl;
    }
};

class Smartphone : public Camera, public MusicPlayer {
public:
    void makeCall() {
        cout << "Making a call" << endl;
    }
};

int main() {
    Smartphone phone;

    phone.takePhoto();
    phone.playMusic();
    phone.makeCall();

    return 0;
}
```


```output
Taking photo
Playing music
Making a call
```

Here, `Smartphone` combines features from:

* `Camera`
* `MusicPlayer`
* Its own `makeCall()` function

### Real-World Example 🌍

A modern device may combine several capabilities.

For example:

```text
Camera
   ↓
          Smartphone
   ↑
Music Player
```

The smartphone can use functionality from both classes while also providing its own functionality.

## 13. The Diamond Problem

A well-known problem with multiple inheritance is called the **Diamond Problem**.

Consider:

```text
        A
       / \
      B   C
       \ /
        D
```

Here:

* `B` inherits from `A`.
* `C` inherits from `A`.
* `D` inherits from both `B` and `C`.

Therefore, `D` can receive two paths to `A`.

This can cause ambiguity.

### Example

```cpp
class A {
public:
    int value = 10;
};

class B : public A {
};

class C : public A {
};

class D : public B, public C {
};
```

Now:

```cpp
D obj;

// obj.value;   // Ambiguous
```

The compiler cannot decide whether `value` should come from:

```text
D → B → A
```

or:

```text
D → C → A
```

---

## 14. Virtual Inheritance

C++ provides **virtual inheritance** to solve the diamond problem.

```cpp
#include <iostream>
using namespace std;

class A {
public:
    int value = 10;
};

class B : virtual public A {
};

class C : virtual public A {
};

class D : public B, public C {
};

int main() {
    D obj;

    cout << obj.value << endl;

    return 0;
}
```


```output
10
```

With virtual inheritance, `B` and `C` share a single `A` base subobject within `D`.

### Important

Virtual inheritance is different from a **virtual function**.

| Feature             | Purpose                                                   |
| ------------------- | --------------------------------------------------------- |
| Virtual function    | Supports runtime polymorphism                             |
| Virtual inheritance | Helps avoid duplicate base classes in a diamond hierarchy |

---

## 15. Multiple Inheritance with Different Base Types

A class can inherit from more than two classes.

```cpp
class A {
};

class B {
};

class C {
};

class D : public A, public B, public C {
};
```

Here, `D` inherits from:

* `A`
* `B`
* `C`

However, multiple inheritance should be used carefully because large inheritance hierarchies can become difficult to understand and maintain.

---

## 16. Advantages of Multiple Inheritance

### 1. Combines Functionality

A class can combine features from multiple base classes.

### 2. Code Reuse

Existing classes can be reused instead of writing the same functionality again.

### 3. Models Multiple Roles

A class can represent multiple capabilities or roles.

### 4. Useful for Complex Designs

Some software designs naturally require a class to inherit from multiple interfaces or base classes.

---

## 17. Disadvantages of Multiple Inheritance

### 1. Ambiguity

Two base classes may contain members with the same name.

### 2. Diamond Problem

Multiple inheritance can create duplicate paths to the same base class.

### 3. More Complex Code

Large inheritance hierarchies can be harder to understand.

### 4. Maintenance

Changes in multiple base classes can make the derived class more difficult to maintain.

---

## 18. Multiple Inheritance vs Single Inheritance

| Feature                | Single Inheritance | Multiple Inheritance                |
| ---------------------- | ------------------ | ----------------------------------- |
| Number of base classes | One                | Two or more                         |
| Complexity             | Usually simpler    | Can be more complex                 |
| Code reuse             | Yes                | Yes                                 |
| Ambiguity risk         | Lower              | Higher                              |
| Diamond problem        | No                 | Possible                            |
| Example                | `Dog → Animal`     | `Smartphone → Camera + MusicPlayer` |

## 19. Common Mistakes

### Mistake 1: Calling an Ambiguous Function

```cpp
obj.show();
```

If both base classes have `show()`, this may be ambiguous.

Use:

```cpp
obj.A::show();
```

or:

```cpp
obj.B::show();
```

---

### Mistake 2: Forgetting the Inheritance List

Incorrect:

```cpp
class C {
};
```

If `C` should inherit from `A` and `B`, write:

```cpp
class C : public A, public B {
};
```

---

### Mistake 3: Confusing Virtual Inheritance with Virtual Functions

These are different concepts.

```cpp
virtual void show();
```

is related to virtual functions and runtime polymorphism.

```cpp
class B : virtual public A {
};
```

is related to virtual inheritance and the diamond problem.

---

### Mistake 4: Ignoring Construction Order

For:

```cpp
class C : public A, public B {
};
```

the construction order is:

```text
A → B → C
```

Do not assume the order depends on the order of constructor calls written inside `C`.

---

## 20. Key Points

* Multiple inheritance allows one class to inherit from multiple base classes.
* The syntax uses multiple base classes separated by commas.
* A derived class can use accessible members from all its base classes.
* Name conflicts can create ambiguity.
* Scope resolution can be used to select a specific base class member.
* Base constructors are called before the derived constructor.
* Destructors execute in the reverse order of construction.
* The diamond problem can occur in certain multiple-inheritance structures.
* Virtual inheritance can solve the diamond problem by sharing a common base subobject.
* Virtual inheritance and virtual functions are different concepts.
* Multiple inheritance should be used carefully because it can increase complexity.
