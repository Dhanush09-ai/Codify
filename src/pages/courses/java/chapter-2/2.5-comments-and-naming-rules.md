# Chapter 2: Java Fundamentals

## Section 5: Comments and Naming Rules

When writing Java programs, it is important to make code easy to understand and follow Java's naming rules.

Two useful concepts are:

* **Comments** — notes written inside the code for humans.
* **Naming rules** — rules for choosing valid names for variables, methods, classes, and other identifiers.

---

## 1. What Are Comments?

A **comment** is text written in a program that is ignored by the Java compiler.

Comments are mainly used to:

* Explain what the code does.
* Make code easier to understand.
* Add notes for yourself or other programmers.
* Temporarily explain or disable a line of code.

Comments do not affect the output of a program.

---

## 2. Single-Line Comments

A single-line comment starts with `//`.

Everything after `//` on that line is treated as a comment.

Example:

```java id="k5m8qx"
public class Main {
    public static void main(String[] args) {
        // This is a comment
        System.out.println("Hello, Java!");
    }
}
```

```output id="r7p3nc"
Hello, Java!
```

The comment is not displayed in the output.

---

## 3. Comments After Code

A comment can also be written after a statement.

Example:

```java id="v2c6ma"
public class Main {
    public static void main(String[] args) {
        int age = 18; // Store the student's age

        System.out.println(age);
    }
}
```


```output id="q9w4ks"
18
```

The compiler ignores the comment and executes the Java statement.

---

## 4. Multi-Line Comments

A multi-line comment starts with `/*` and ends with `*/`.

It can contain multiple lines.

Example:

```java id="m8d2zp"
/*
   This program displays
   a simple message.
*/
public class Main {
    public static void main(String[] args) {
        System.out.println("Welcome to Java!");
    }
}
```


```output id="x4n7bc"
Welcome to Java!
```

Everything between `/*` and `*/` is treated as a comment.

---

## 5. Documentation Comments

Java also supports documentation comments.

They start with `/**` and end with `*/`.

Example:

```java id="t6p3va"
/**
 * This program displays a welcome message.
 */
public class Main {
    public static void main(String[] args) {
        System.out.println("Welcome to Java!");
    }
}
```


```output id="e9k5rm"
Welcome to Java!
```

Documentation comments are commonly used to describe classes and methods and can be used to generate Java documentation.

For beginners, remember the three common comment styles:

| Comment      | Use                   |
| :----------- | :-------------------- |
| `//`         | Single-line comment   |
| `/* ... */`  | Multi-line comment    |
| `/** ... */` | Documentation comment |

---

## 6. What Are Identifiers?

An **identifier** is a name given to a programming element.

Examples include names of:

* Variables
* Methods
* Classes
* Objects

For example:

```java id="p4z8ny"
int age = 18;
```

Here:

* `int` is a data type.
* `age` is an identifier.
* `18` is the value.

---

## 7. Rules for Naming Identifiers

Java has rules that must be followed when naming identifiers.

### Rule 1: Names can contain letters, digits, `_`, and `$`

For example:

```text id="w5q2df"
studentName
student1
_total
$amount
```

These can be valid identifiers.

---

### Rule 2: An identifier cannot start with a digit

This is invalid:

```text id="n8c4va"
1student
```

This is valid:

```text id="b3m7qx"
student1
```

A digit can be used after the first character.

---

### Rule 3: Spaces are not allowed

This is invalid:

```text id="z6k9pc"
student name
```

Use a single name instead:

```text id="f2r5wm"
studentName
```

---

### Rule 4: Java is case-sensitive

Java treats uppercase and lowercase letters as different.

For example:

```text id="u7x3qa"
age
Age
AGE
```

These are three different names.

Example:

```java id="c9m2vk"
public class Main {
    public static void main(String[] args) {
        int age = 18;
        int Age = 20;

        System.out.println(age);
        System.out.println(Age);
    }
}
```


```output id="h4p8zs"
18
20
```

---

### Rule 5: Keywords cannot be used as identifiers

Java has reserved **keywords** such as:

```text id="y2n6cd"
class
int
if
else
for
while
return
static
public
```

These words have special meanings in Java.

For example, this is invalid:

```java id="q8v3mf"
int class = 10;
```

`class` is a Java keyword, so it cannot be used as a variable name.

---

## 8. Naming Conventions

Naming conventions are recommended ways of naming things.

They are not the same as Java's identifier rules.

Following conventions makes code easier to read.

### Variables and Methods

Java commonly uses **camelCase** for variable and method names.

Examples:

```text id="s5m9xa"
studentName
totalMarks
calculateAverage
getStudentName
```

Example:

```java id="d7k2pn"
public class Main {
    public static void main(String[] args) {
        int totalMarks = 95;

        System.out.println(totalMarks);
    }
}
```


```output id="a3x8vc"
95
```

---

## 9. Class Names

Class names commonly use **PascalCase**.

Examples:

```text id="j6q4mb"
Student
StudentRecord
BankAccount
Main
```

Each word starts with an uppercase letter.

Example:

```java id="r2v7ks"
public class StudentRecord {
    public static void main(String[] args) {
        System.out.println("Student Record");
    }
}
```


```output id="n8c5yd"
Student Record
```

---

## 10. Constants

Constants are often written using **UPPER_SNAKE_CASE**.

For example:

```text id="m4z9qw"
MAX_MARKS
PI_VALUE
COLLEGE_NAME
```

Example:

```java id="x7p3kc"
public class Main {
    public static void main(String[] args) {
        final int MAX_MARKS = 100;

        System.out.println(MAX_MARKS);
    }
}
```


```output id="v5n2ra"
100
```

---

## 11. Good and Bad Naming Examples

Good names make code easier to understand.

| Good Name        | Poor Name |
| :--------------- | :-------- |
| `studentName`    | `sn`      |
| `totalMarks`     | `tm`      |
| `studentAge`     | `x`       |
| `calculateTotal` | `ct`      |

For example:

```java
int studentAge = 18;
```

is easier to understand than:

```java
int x = 18;
```

Both may work, but the first name clearly explains what the value represents.

---

## 12. Rules vs Naming Conventions

It is important to understand the difference.

### Naming Rules

Rules determine whether an identifier is **valid Java code**.

For example:

```text
studentName
student1
```

are valid identifiers.

But:

```text
1student
student name
```

are not valid identifiers.

### Naming Conventions

Conventions are recommended styles that make code easier to read.

For example:

```text
studentName
totalMarks
```

are commonly preferred over:

```text
StudentName
totalmarks
```

for variable names.

---

## Key Points

* Comments are ignored by the Java compiler.
* `//` is used for single-line comments.
* `/* ... */` is used for multi-line comments.
* `/** ... */` is used for documentation comments.
* Identifiers are names given to programming elements.
* Identifiers cannot start with a digit.
* Spaces are not allowed in identifiers.
* Java is case-sensitive.
* Java keywords cannot be used as identifiers.
* Variable and method names commonly use **camelCase**.
* Class names commonly use **PascalCase**.
* Constants commonly use **UPPER_SNAKE_CASE**.
